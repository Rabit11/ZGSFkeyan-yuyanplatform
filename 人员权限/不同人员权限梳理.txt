6008端口不同人员权限梳理
==========================



一、权限体系总览
================

6008平台不是“一个人只对应一个固定角色”的简单权限模式，而是由四层权限共同决定最终能力。

第一层：登录任职身份
--------------------

决定：
1. 登录后的基础首页。
2. 默认功能栏和菜单包。
3. 组织数据范围，例如全公司、本单位、本人项目或经手项目。
4. 是否属于领导、管理、项目、总师、财务或管理员类别。

平台当前定义15类登录任职身份。

第二层：项目岗位
----------------

决定用户在某一个具体项目中可以办理什么业务，例如：
1. 是否可完善项目基本信息。
2. 是否可编制或销项里程碑。
3. 是否可填报计划或经费。
4. 是否可发起申报、审批、变更和验收。
5. 是否可维护成果、协作评价和项目成员岗位。

平台当前定义13类项目岗位、18项项目办理权限。

第三层：数据范围
----------------

任职记录支持以下数据范围：
1. self：仅本人。
2. project：本人参与项目。
3. dept：本部门。
4. unit：本单位。
5. hq：全公司/总部范围。
6. selected：指定范围。

最终能看到的数据还会受到单位、部门、当前任职、具体项目成员关系及接口业务条件限制。

第四层：独立专项授权
--------------------

以下权限不完全由普通登录角色或项目岗位自动决定：
1. 表单维护权限：单独控制是否能进入预研项目总表/分表维护工具，以及维护范围。
2. 立项审批结果权限：单独控制是否可办理或查看立项审批结果相关能力；系统管理员强制具备。
3. 项目岗位权限矩阵维护：只有系统管理员可配置。
4. 成员、渠道字典、流程模板和审计日志维护：属于系统管理员配置权限。


二、权限合并原则
================

1. 登录身份与项目岗位不是同一概念。
   - 登录身份表示“这个人以什么组织身份进入平台”。
   - 项目岗位表示“这个人在某个项目中承担什么职责”。

2. 同一个人可以有多个单位、部门和任职身份。
   - 主任职用于默认登录。
   - 其他有效任职可以切换。
   - 切换后重新计算登录身份、单位、部门、数据范围和功能栏。

3. 同一个人在不同项目中可以担任不同项目岗位。
   - 某项目是项目负责人，另一项目可以是技术负责人或项目主管。
   - 项目办理权限必须按当前项目计算，不能把一个项目的岗位权限带到另一个项目。

4. 同一项目担任多个岗位时，办理权限取并集。
   例如某人在同一项目同时是项目负责人和技术负责人，则同时获得这两个岗位在该项目中的已配置权限。

5. 功能栏按“登录身份 ∪ 项目岗位功能包”生成，但受组织资格上限限制。
   - 登录身份提供基础菜单。
   - 已担任的项目岗位可以补充相关业务菜单。
   - 补充菜单不表示可办理全部项目，只能办理本人实际担任岗位的项目。
   - 公司领导仍保持只读，不能因项目岗位获得业务办理菜单。
   - 财务人员受到财务功能边界限制。

6. 能进入项目不等于能办理项目。
   所有能够进入该项目的人原则上可看到项目详情页签和基本概览字段，具体按钮和写操作由项目岗位权限判断。

7. 后端权限判断优先。
   页面隐藏菜单或按钮只用于交互提示，关键操作必须经过后端角色、数据范围、项目岗位、流程状态和记录状态校验。


三、15类登录任职身份权限
=========================

3.1 公司领导（leader）
----------------------

人员定位：公司领导、决策查看人员。

数据范围：
1. 全公司项目。
2. 只读。

基础功能入口：
1. 预研指挥舱/科研预研信息管理大屏。
2. 可视化驾驶舱。
3. 项目台账。
4. 成果转化台账。

允许事项：
1. 查看全公司项目和经营分析信息。
2. 查看项目台账、成果转化和项目内经费信息。
3. 查看大屏与驾驶舱。

禁止或默认不开放事项：
1. 不修改项目台账。
2. 不填报业务数据。
3. 不办理审批和评审。
4. 不进入独立预警办理菜单。
5. 不进行全量数据导出。
6. 不进入表单维护。
7. 不进入配置中心。
8. 不办理经费或拨付。


3.2 总部责任处室处长（hqHead）
--------------------------------

人员定位：总部科技管理部门处长，负责公司级统筹、组织评价和审签把关。

数据范围：全公司。

基础功能入口：
1. 工作台、待办审批。
2. 项目台账、成果转化台账。
3. 审批中心、协作评价。
4. 预研指挥舱、驾驶舱、预警中心。
5. 表单维护入口在具备专项授权时显示。

允许事项：
1. 查看、添加、编辑、删除项目台账记录。
2. 对成果转化进行审核、备案和进度督办。
3. 进行处长审签、组织评价和统筹管理。
4. 查看和督办全公司预警。
5. 使用管理分析驾驶舱和预研大屏。
6. 支持全公司范围导出。
7. 表单维护默认授权为总部全部台账，可被成员权限配置调整。

限制：
1. 项目团队填报字段仍需按业务流程和项目岗位办理。
2. 无成员管理、渠道字典和权限矩阵配置权。
3. 无独立经费经办职责，项目内经费以查看为主。


3.3 总部科研项目主管（hqStaff）
--------------------------------

人员定位：总部科技部日常科研项目主管，负责公司级进度督办、备案审核和日常流转。

数据范围：全公司。

基础功能入口：
1. 工作台、待办审批。
2. 项目台账、成果转化台账。
3. 审批中心、协作评价。
4. 预研指挥舱、驾驶舱、预警中心。
5. 表单维护入口按人员授权显示。

允许事项：
1. 查看、添加、编辑、删除项目台账记录。
2. 成果转化审核、备案和督办。
3. 总部主管审签和备案审核。
4. 查看和督办全公司预警。
5. 支持全公司范围导出。
6. 可按单独授权维护总部全部、本单位、指定渠道、指定项目类型或本人范围表单。

限制：
1. Excel批量导入必须具备表单维护专项授权。
2. 没有表单专项授权时不能进入表单维护页面。
3. 无配置中心权限。
4. 无独立经费经办菜单。


3.4 单位科研管理部门负责人（unitHead）
--------------------------------------

人员定位：二级单位科技管理部门负责人或部长。

数据范围：
1. 本单位项目。
2. 本人另行担任项目岗位的项目。

基础功能入口：
1. 工作台、待办审批。
2. 本单位项目台账、成果转化。
3. 审批中心、协作评价。
4. 驾驶舱、预警中心。
5. 表单维护仅在获得专项授权时显示。

允许事项：
1. 本单位项目查看、添加、编辑和删除。
2. 本单位成果转化审核和进度督办。
3. 本单位管理审签。
4. 指定或转办本单位项目岗位。
5. 查看本单位管理分析和预警。

限制：
1. 不能查看和导出全公司数据。
2. 默认不能进入预研信息大屏。
3. 默认没有表单维护权限。
4. 无配置中心权限。
5. 无独立经费经办职责。


3.5 单位项目主管（unitStaff）
--------------------------------

人员定位：二级单位科研项目日常主管。注意：它属于管理团队，与项目团队中的“项目主管”不是同一身份。

数据范围：
1. 本单位项目。
2. 本人另行担任项目岗位的项目。

基础功能入口：
1. 工作台、待办审批。
2. 本单位项目台账、成果转化。
3. 审批中心、协作评价。
4. 驾驶舱、预警中心。
5. 表单维护仅在获得专项授权时显示。

允许事项：
1. 本单位项目查看、添加、编辑和删除。
2. 本单位成果转化查看和督办。
3. 本单位主管审签。
4. 指定或转办本单位项目岗位。
5. 查看本单位预警和管理分析。

限制：
1. 不能查看全公司范围数据。
2. 无全量数据导出。
3. 默认无预研大屏。
4. 默认无表单维护。
5. 无配置中心和独立经费经办菜单。


3.6 项目负责人（owner）
----------------------

人员定位：项目总负责人或项目责任人。

数据范围：仅本人关联项目。

基础功能入口：
1. 工作台、待办审批、我的预警。
2. 项目台账。
3. 里程碑、计划、评估检查、项目变更。
4. 经费办理。

允许事项：
1. 完善关联项目基本信息。
2. 编制及销项里程碑。
3. 维护交付物。
4. 填报评估检查和项目变更。
5. 发起验收申请和相关审批。
6. 更新关联项目成果转化。
7. 对协作单位进行评价。
8. 指定或转办本项目岗位。
9. 填报经费预算。
10. 随时填报经费使用明细并上传核销材料。
11. 经费材料由单位财务部长审核，通过后由总部归集。

限制：
1. 只能操作本人关联项目。
2. 无全量导出。
3. 无驾驶舱和预研大屏。
4. 无表单维护和配置中心。
5. 实际按钮以当前项目岗位矩阵和流程状态为准。


3.7 技术负责人（techLead）
---------------------------

人员定位：项目技术执行责任人。

数据范围：仅本人关联项目。

基础功能入口：
1. 默认首页为里程碑。
2. 工作台、待办审批、我的预警。
3. 项目台账。
4. 里程碑办理。

允许事项：
1. 编制里程碑计划。
2. 里程碑销项并上传完成佐证。
3. 维护和交付交付物。
4. 办理相关技术节点审批。
5. 超期后按项目变更流程处理。
6. 按默认项目岗位矩阵可完善基本信息、填报经费预算及发起相关变更。

限制：
1. 不默认展开项目申报和计划管理全套菜单。
2. 成果转化以查看为主，不默认修改。
3. 无全量导出、驾驶舱、预研大屏、表单维护和配置中心。
4. 无经费核销材料上传权限，除非项目岗位矩阵另行配置。


3.8 项目主管（projectPm）
-------------------------

人员定位：项目团队内部负责计划与变更协同的项目主管，不是单位管理团队的单位项目主管。

数据范围：仅本人关联项目。

基础功能入口：
1. 默认首页为计划管理。
2. 工作台、待办审批、我的预警。
3. 项目台账。
4. 计划管理、项目变更。

允许事项：
1. 完善项目基本信息。
2. 计划填报和办结。
3. 项目变更协同。
4. 外协合同登记。
5. 评估检查填报。
6. 发起相关审批。
7. 查看经手项目成果转化。

限制：
1. 无独立经费菜单。
2. 无全量导出、驾驶舱、预研大屏、表单维护和配置中心。
3. 只能办理本人担任项目岗位的项目。


3.9 项目联系人（contactLogin）
--------------------------------

人员定位：项目申报和立项材料责任人。

数据范围：仅本人关联项目。

基础功能入口：
1. 工作台、待办审批、我的预警。
2. 项目台账。
3. 项目申报、里程碑、计划管理、评估检查、项目变更。

允许事项：
1. 发起项目申报。
2. 上传立项备案材料。
3. 发起审批并上传材料。
4. 完善项目基本信息。
5. 编制和销项里程碑。
6. 填报评估检查和项目变更。
7. 更新关联项目成果转化。
8. 默认可指定或转办本项目岗位。
9. 按默认矩阵可填报经费预算，但不负责上传核销材料。

限制：
1. 经费核销由项目负责人发起。
2. 无全量导出、驾驶舱、预研大屏、表单维护和配置中心。
3. 只能办理本人关联项目。


3.10 一级总师（chief1）
-----------------------

人员定位：公司级责任总师，负责重要技术节点把关。

数据范围：本人被指定为一级总师的经手项目。

基础功能入口：
1. 默认首页为评审工作台。
2. 工作台、待办审批。
3. 项目台账、风险关注。
4. 评审工作台。

允许事项：
1. 查看本人经手项目。
2. 进行重要节点技术审核和技术指导。
3. 查看经手项目成果转化和风险。
4. 默认项目岗位矩阵包含经费预算填报标识，但实际业务仍需结合流程节点校验。

限制：
1. 默认无项目台账修改权。
2. 无全量导出和独立驾驶舱菜单。
3. 无预研大屏、表单维护、经费办理和配置中心。


3.11 二级总师（chief2）

人员定位：单位级责任总师，负责单位级技术把关。

数据范围：本人被指定为二级总师的经手项目，通常属于本单位。

3. 查看经手项目成果转化和风险。
4. 默认项目岗位矩阵包含经费预算填报标识，实际操作仍受流程校验。

限制：
1. 默认无项目台账修改权。
2. 无全量导出、驾驶舱、预研大屏、表单维护、经费办理和配置中心。


3.12 总部财务主管（finHq）
-------------------------

人员定位：总部财务经费执行与拨付核对人员。

数据范围：总部项目经费。

基础功能入口：
1. 默认首页为经费台账。
2. 工作台、待办审批。
3. 经费台账、总部拨付。
4. 项目台账。

允许事项：
1. 从经费视角查看项目台账。
2. 归集二级单位财务部长审核通过的经费信息。
3. 进行总部经费核对和异常监管。
4. 进入总部拨付管控，协同拨付核对。

限制：
1. 无科研业务数据修改权。
2. 无成果转化、综合驾驶舱、预研大屏和独立预警菜单。
3. 无表单维护、全量数据导出和配置中心。


3.13 单位财务部长（finHead）
---------------------------

人员定位：二级单位财务审核负责人。

数据范围：本单位项目经费。

基础功能入口：
1. 工作台、待办审批。
2. 经费台账。
3. 与本单位有关的总部拨付信息。
4. 项目台账。

允许事项：

2. 审核项目负责人提交的经费使用明细和核销材料。
3. 审核通过后自动报送总部归集。
4. 查看与本单位相关的拨付信息。

限制：
1. 不修改科研业务数据。
2. 无成果转化、驾驶舱、预研大屏和独立预警菜单。
3. 无表单维护、全量导出和配置中心。

3.15 系统管理员（admin）
------------------------

人员定位：科研项目处指定的平台配置与运维人员。

数据范围：全平台。

基础功能入口：
1. 工作台、待办审批和预警中心。
2. 项目申报、里程碑、计划、评估检查、项目变更和经费办理。
3. 项目台账、经费台账、成果转化。
4. 预研指挥舱、驾驶舱、总部拨付和评审工作台。
5. 渠道字典、成员管理、权限矩阵、流程模板、审计日志和表单维护。

允许事项：
1. 维护成员账号、任职和身份。
2. 重置密码和回收账号。
3. 维护渠道字典、角色权限矩阵和流程模板。
4. 查看审计日志。
5. 查看、添加、编辑、删除全平台项目台账。
6. 进入预研大屏、驾驶舱和预警中心。
7. 维护全部表单台账，执行总表覆盖、分表合并、导出、删除、清空和撤回。
8. 后端项目权限判断中，管理员被赋予全部18项项目办理权限。
9. 系统管理员强制具备立项审批结果权限。

管理保护：
1. 当前管理员不能删除自己。
2. 当前管理员不能把自己设置为已离岗。
3. 系统中唯一管理员不能被删除。
4. 系统中唯一管理员不能被取消管理员身份。

业务边界：
1. 管理员的设计定位是平台配置和运维。
2. 项目权限实现允许管理员进行全量操作，但正式业务仍应遵循原有流程、状态和审计要求，不应以运维身份替代正常业务责任人办理。
3. 角色权限说明中不向管理员默认开放普通“全量数据导出”概念，但表单维护模块允许管理员按其专用权限导出台账。

七、表单维护专项权限
====================

表单维护权限用于预研项目总表、专项分表、Excel导入、导出、校验、删除和撤回，不等同于普通项目台账权限。

1. hq：总部全部台账
   - 查看、编辑、删除和导出全部表单记录。
   - 上传总表覆盖和分表合并。
   - 清空全部项目。
   - 维护项目类型主管分工。

2. unit：本单位
   - 只维护本单位相关记录。
   - 不允许覆盖导入总表和清空全部项目。

3. channel：指定渠道
   - 只维护授权渠道记录。
   - 必须指定一个或多个授权渠道。

4. type：指定项目类型
   - 只维护授权项目类型记录。
   - 必须指定一个或多个项目类型。

5. self：仅本人
   - 只维护负责人或最后更新人与当前用户匹配的记录。

6. 默认规则
   - 系统管理员默认具备全部台账权限。
   - 总部责任处室处长默认具备全部台账权限。
   - 总部科研项目主管按人员授权，现有设计说明为科技部实名账号可默认授权，但最终以成员记录字段为准。
   - 非总部科技管理单位在成员保存时，后台会自动关闭表单维护权限。


八、立项审批结果专项权限
========================

1. 该权限独立保存为declare_result_access。
2. 系统管理员强制具备该权限。
3. 其他人员由系统管理员在成员管理中单独分配。
4. 它用于控制立项流程中“审批结果”步骤或同类能力。
5. 它不应通过普通项目岗位矩阵自动推断。
6. 当前成员管理页面中该配置区受CSS影响可能不可见，但后端权限字段和判断仍然存在。


九、审批与流程权限补充规则
==========================

1. 菜单可见不等于当前节点可办理。
2. 审批步骤通常要求当前用户为该步骤指派人、指派工号或对应项目岗位人员。
3. 系统管理员可通过后台全局权限通过部分检查，但操作仍会被记录审计。
4. 项目负责人、项目联系人、技术负责人、项目主管、管理人员、总师和财务人员分别在流程中承担发起、材料、技术审核、管理审签或经费审核职责。
5. 里程碑超期后不能直接改日期，必须走项目变更流程。
6. 评估结论或检查材料上传要求本项目团队或二级单位管理岗位具备对应权限。
7. 项目岗位转办后，在途节点会随岗位改派到新人员并记录审计。


十、财务权限边界
================

1. 项目负责人
   - 发起经费使用明细和核销材料。

2. 单位财务部长
   - 审核本单位项目负责人提交的材料。
   - 审核通过后信息进入总部归集。

3. 单位财务主管
   - 查看和协助核对。
   - 不发起核销，不直接修改经费台账。

4. 总部财务主管
   - 汇总单位审核通过的经费数据。
   - 进行总部经费执行和拨付核对。

5. 总部拨付管控入口
   - 系统管理员可进入。
   - 总部管理人员可进入。
   - 总部财务人员可进入。
   - 单位财务主管不可进入。

6. 财务人员原则上不能修改科研项目业务数据。


十一、配置中心权限
==================

系统管理员独有配置能力：
1. 渠道字典。
2. 成员管理。
3. 多任职管理和身份切换配置。
4. 角色权限矩阵。
5. 项目岗位办理权限矩阵。
6. 流程模板。
7. 审计日志。
8. 全量表单维护。

非管理员即使具有总部管理身份，也不能直接进入成员管理、角色权限矩阵、渠道字典和流程模板维护。


十二、账号与任职状态对权限的影响
================================

1. 已离岗账号
   - 不能继续按在岗账号正常使用业务权限。
   - 管理员可在成员管理中回收或恢复状态。

2. 任职有效期
   - 任职状态必须为有效且在有效期内，才能用于身份和数据范围计算。

3. 主任职
   - 作为默认登录身份。
   - 决定账号主角色、单位、部门、职称和默认数据范围。

4. 兼任
   - 有效兼任可切换为当前身份。
   - 不删除主任职，只改变本次会话使用的任职。

5. 删除当前使用的任职
   - 后台清除会话中的当前任职标识。
   - 用户重新回到有效主任职。

6. 密码重置
   - 账号全部旧会话失效，需要重新登录并重新计算权限。

十四、迁移到Vue + Spring Boot时必须保留的权限规则
================================================

1. 保留15类登录任职身份及其角色、范围和标题映射。
2. 保留一个账号多条任职、一个主任职和会话身份切换机制。
3. 保留“登录身份≠项目岗位”的双层模型。
4. 保留同项目多岗位权限取并集。
5. 保留13类项目岗位和18项可配置办理权限。
6. 保留项目页签/概览信息始终可见、业务按钮按岗位控制的规则。
7. 保留全公司、本单位、本人、经手项目和指定范围的数据隔离。
8. 保留组织资格上限，不能仅通过项目岗位绕过领导只读或财务边界。
9. 保留表单维护的独立授权和五种维护范围。
10. 保留立项审批结果独立授权。
11. 保留管理员自我删除、唯一管理员和自我停用保护。
12. 保留流程节点指派、项目岗位、记录状态和权限矩阵的联合校验。
13. 保留所有关键权限变更、身份切换、岗位指定和岗位转办审计。
14. 前端隐藏按钮不能代替Spring Boot Service中的权限判断。
15. 不因技术框架更换扩大或缩小任何现有人员的数据范围。


十五、权限验收清单
==================

1. 登录身份
   □ 15类任职身份均可正确识别。
   □ 主任职决定默认首页和菜单。
   □ 兼任切换后菜单、单位、部门和数据范围立即更新。
   □ 无效、停用或过期任职不能继续授权。

2. 菜单
   □ 各角色基础菜单与本文一致。
   □ 项目岗位可以补充业务菜单，但只作用于本人有岗位的项目。
   □ 公司领导始终只读。
   □ 单位账号不能通过岗位获得总部专属大屏或全量表单权限。
   □ 单位财务主管不能进入总部拨付。

3. 数据范围
   □ 总部人员看到全公司授权数据。
   □ 单位管理人员只看到本单位和本人任职项目。
   □ 项目团队只看到本人关联项目。
   □ 总师只看到本人经手项目。
   □ 财务人员只看到对应组织范围的经费数据。

4. 项目岗位
   □ 13类项目岗位均能被指定和转办。
   □ 18项权限均由后端检查。
   □ 同项目多岗位正确取并集。
   □ 不同项目之间的岗位权限不串用。
   □ 管理员修改矩阵后全平台项目立即按新矩阵判断。

5. 专项授权
   □ 无表单维护授权不能打开页面或调用接口。
   □ 五种表单维护范围过滤正确。
   □ 只有总部全量或管理员可覆盖总表、清空全部和维护主管分工。
   □ 立项审批结果权限单独生效。

6. 安全保护
   □ 唯一管理员不能删除或取消管理员身份。
   □ 当前管理员不能删除或停用自己。
   □ 已离岗账号权限被回收。
   □ 密码重置后旧会话全部失效。
   □ 权限修改、身份切换和岗位转办均有审计记录。
