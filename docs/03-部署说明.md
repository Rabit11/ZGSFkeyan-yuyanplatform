# 部署说明

## 一、环境要求

| 组件 | 版本 | 备注 |
| --- | --- | --- |
| Node.js | ≥ 18（推荐 20 LTS） | 前端构建 |
| JDK | 17 | 后端运行 |
| Maven | ≥ 3.8 | 后端构建 |
| 数据库 | 阿里云 PolarDB（MySQL 8.0 兼容） | 或本地 MySQL 8.0 |

## 二、数据库初始化

1. 在 PolarDB 控制台创建数据库 `rpm`（字符集 `utf8mb4`）。
2. 若通过公网连接，需在 PolarDB **白名单**中加入应用服务器出口 IP。
3. 执行建表脚本：

```bash
mysql -h <PolarDB 集群地址> -P 3306 -u rpm -p rpm \
  < backend/src/main/resources/db/schema.sql
```

脚本包含 33 张表的建表语句与初始化数据（组织、角色、演示用户、15 个项目渠道、数据字典）。

4. （可选）对齐人员花名册与演示业务样本：

```bash
mysql -h <PolarDB 集群地址> -P 3306 -u rpm -p rpm \
  < backend/src/main/resources/db/personnel_roster_v1.sql

mysql -h <PolarDB 集群地址> -P 3306 -u rpm -p rpm \
  < backend/src/main/resources/db/seed_demo_projects.sql
```

`seed_demo_projects.sql` 写入约 8 个演示项目及里程碑、经费、变更、申报、成果转化、协作单位黑名单等，按业务编号去重，可重复执行。
## 三、后端部署

### 1. 修改配置

`backend/src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://<PolarDB 集群地址>:3306/rpm?useUnicode=true&characterEncoding=utf8mb4&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: rpm
    password: <生产密码>
rpm:
  jwt:
    secret: <随机密钥，生产环境务必替换>
    expire-hours: 12
```

生产环境建议使用环境变量注入，避免明文入库：

```bash
export SPRING_DATASOURCE_URL="jdbc:mysql://..."
export SPRING_DATASOURCE_PASSWORD="..."
export RPM_JWT_SECRET="..."
```

### 2. 构建与启动

```bash
cd backend
mvn clean package -DskipTests
java -jar target/rpm-backend-1.0.0.jar --spring.profiles.active=prod
```

服务默认监听 `8080`，可通过 `--server.port` 覆盖。

### 3. 验证

```bash
curl http://localhost:8080/api/dict/PROJECT_LEVEL
# 返回 { "code": 0, "msg": "ok", "data": [ ... ] }
```

## 四、前端部署

### 开发模式

```bash
cd frontend
npm install
npm run dev            # http://localhost:5173
```

`vite.config.ts` 已配置 `/api` 代理到 `http://localhost:8080`。

### 生产构建

```bash
npm run build          # 产物输出到 frontend/dist
```

### 对接真实后端

修改 `frontend/.env.production`：

```
VITE_API_BASE=/api
VITE_USE_MOCK=false
```

### Nginx 部署示例

```nginx
server {
    listen 80;
    server_name rpm.example.com;

    root /var/www/rpm/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;   # 支持 history 路由
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

> 前端路由使用 hash 模式（`createWebHashHistory`），无需 Nginx 额外配置即可刷新不 404；
> 上述 `try_files` 为兼容 history 模式的备用配置。

## 七、常见问题

**Q：后端启动报 `Access denied for user`**
A：检查 PolarDB 账号密码与白名单设置，确认数据库名 `rpm` 已创建。

**Q：前端接口 404**
A：确认 `VITE_USE_MOCK` 已设为 `false`，且 vite 代理目标（`http://localhost:8080`）服务已启动。

**Q：登录后立即退回登录页**
A：检查 JWT 密钥配置；若前后端密钥不一致会导致 token 校验失败。

**Q：`mvn compile` 报错**
A：本项目在本机无 JDK 环境下编写，已通过静态自检但未实际编译。请按编译器提示修正，
常见问题为 Lombok 注解处理器未启用（在 IDE 中开启 Annotation Processing 即可）。
