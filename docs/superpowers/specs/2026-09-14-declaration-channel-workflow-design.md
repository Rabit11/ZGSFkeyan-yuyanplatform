# 项目申报按渠道审签设计（待确认）

依据：科研项目信息化管理平台需求V19_1.docx，立项阶段「2.审签流程」。范围仅项目申报、衔接立项备案及相关待办，不改实施、验收、经费、成果转化规则。

## 实现方式

推荐建立申报专用流程模板，由渠道编码选择模板；每一步包含稳定节点编码、名称、类型（填写/审核/办理）、指定岗位和结束行为。前端与 Mock 复用同一模板定义，后端使用相同规则，并用测试对照两端节点序列。选择渠道后显示实际将执行的节点及人员，提交、审核、待办和流转图均使用同一业务规则。

另外两种方式：只在各处增加渠道判断，改动少但容易再次出现展示与执行不一致；引入通用工作流引擎，能力更强但涉及全平台和部署变化，超出本次范围。

3. 科技周：项目负责人填写 → 三级专业总师 → 二级专业总师 → 单位科技部 → 单位科技部门负责人 → 单位分管科技领导 → 总部科技部科技发展处 → 一级总师审核 → 总部科技管理部 → 需求发布 → 技术发展战略委员会审查 → 发布拟立项项目清单。各单位立项通过立项备案衔接，后续实施、验收不纳入申报审批链。

## 人员与权限

按渠道显示节点所需人员选择项；补充独立的分管领导、三级专业总师、委员会及专用部门经办岗位。委员会节点由明确指定的经办账号提交评审结论及意见/纪要，并非系统模拟委员会投票。

单位分管领导不再自动等同于单位科技部长或主管。普通申报审批以指定人员为准，不扩大公共身份权限，不修改其他模块的岗位匹配。提交时若缺少后续节点办理人，明确列出缺项并阻止提交。Mock 同样校验操作人员和当前状态。

## 状态及历史数据

新申报按渠道模板运行；模板版本和节点编码随申报保存，避免后续模板变更改变在途审批路径。在途旧申报维持原审批版本并清楚标注；退回草稿后允许重新选择并完整校验新流程，禁止静默跳过旧审批。已办结记录不重开审批。

审核退回初始填写节点并保留意见；办理/审批成功推进对应模板的下一节点。全部申报节点完成后才进入现有备案准入，不直接转为实施中。线下办理节点记录经办人及佐证，不用普通“审批通过”按钮冒充发布或报批动作。
