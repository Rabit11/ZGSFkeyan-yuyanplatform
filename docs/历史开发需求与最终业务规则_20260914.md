# 科研预研管理平台历史开发需求与最终业务规则沉淀 (V7)

> 来源：本次会话中的全部开发需求讨论、缺陷修复反馈、以及本地验收文档。
> 沉淀时间：2026-09-14
> 目的：统一历史需求口径，避免“旧设计覆盖新规则”，给继续开发/复测提供一份可执行基线。

## 1. 口径定义

**确认层级：**

- `已确认-实现中`：用户明确要求且后续未被反向修正。
- `已确认-待验`：用户要求明确，但未在文档或脚本中看到完整闭环验证。
- `已废弃`：被后续明确新要求替代。

**优先级：**

- 对同一事项，按“最后一次用户明确口头确认”覆盖之前口径。
- 自动化/测试报告为实现依据；若报告未覆盖，则标记 `待验`。
- 截图无法识别的内容会在备注中标明未可视化。

## 2. 核心业务规则（当前按优先级汇总）

### 2.1 组织与人员

- 主部门角色：`王建国`所属主部门口径固定为 `总部科技部科研项目处`。
- 项目阶段流转不允许负责人单方决策：`项目负责人不能自己决定进入立项备案阶段`。
- 已确认 `林晚晴` 为项目团队负责人，且项目负责人具备项目联系人相关权限全集。
- 项目团队联系人权限应继承给项目负责人。
- `毕仲文(100010)` 的财务权限限定为**二级单位财务部长**，用于本单位财务审核/审批，非总部级财务管控口径。
- 新增角色能力要求（页面/功能入口需按角色差异化）：项目团队、项目承担部门负责人、单位科研管理部门负责人、二级单位财务、总部财务财务岗位等。

### 2.2 项目生命周期与状态联动

- 生命周期以“已发生流程节点”为主，页面上需能展开查看全部历史节点与流转过程。
- 用户明确要求“流程信息随项目实际状态动态显示”，节点状态与当前负责人联动。
- `提交审核/提交审查`行为应触发对应流转且可关闭当前弹窗或页面（避免重复操作）。
- 未完成前置条件时不允许越权推进。

### 2.3 里程碑节点与销项

- 里程碑页面要支持：
  - 节点序号、节点名称。
  - 交付物清单作为该节点子表。
  - 允许增加交付物行数。
  - 允许新增里程碑节点。
- 节点销项提交应当先进入审核，不直接判定完成。
- 销项闭环链路为：
  1. `项目团队负责人`提交销项信息。
  2. `项目承担部门负责人`审核。
  3. `单位科研管理部门负责人`审核。
  4. 全流程审核通过后节点完成并允许核销。
- 项目阶段中需要待办区分：实现阶段新增 `待我审核` 专栏，仅对有审核任务的人展示。

### 2.4 经费与预算核销

- 对“经费总核”流程确认：
  - 依次流转到 `二级单位财务负责人` -> `总部财务主管`。
  - 弹窗提醒/待办按当前节点顺序推送。
- 对“预算与核销”在当前状态时按阶段顺序推送给对应财务角色。
- 预算核销（里程碑闭环后）最终明确为：
  - `二级单位财务`上传付款凭证。
  - 完成本级核销。
  - 数据自动同步至`总部经费看板`。
- 对此前“负责人直接上传销项/预算节点核销”口径已修订：必须由二级单位财务角色处理上传与核销起始。

### 2.5 审批消息与待办推送

- 审批消息必须推送到对应人员页面，不出现“看得到节点但个人页无该审核任务”。
- 审批弹窗/待办页面要按实际责任人、当前状态、当前环节顺序推送，不做无效泛推。
- 需要保留“审核通过/退回”动作入口，避免只读态误报。

### 2.6 项目视图与页面体验

- `当前项目下拉`应可检索、显示一致，不出现明明存在却查不到或编码错乱的问题。
- 项目名称/项目编号显示统一且稳定。
- 自动闪烁问题需要修复：避免页面在请求或刷新过程中频繁重渲染导致页面抖动。
- 里程碑核销、报备、财务表单应有明确字段编辑/只读边界，未满足条件时不允许提交。

### 2.7 数据一致性与样本数据

- 检查并修正页面、看板中“信息不一致”场景（如同一指标在不同区块口径不一致）。
- 需求方提出“去除已有样本数据并只做平台级别bug排查”，应作为运维清理和回归计划的一部分。
- 已识别数据展示/编码问题：界面中文乱码、异常历史样本与聚合口径污染等需统一排查。

## 3. 里程碑：已废弃口径（按时间后推）

| 废弃时间/版本 | 旧口径 | 新口径 |
|---|---|---|
| 后续修订 | 负责人可自行进入`立项备案` | 负责人不能自行决定进入`立项备案`，需按流程/审核推进 |
| 后续修订 | 任何人可直接完成里程碑核销 | `项目团队负责人上传` 后经部门责任人链路审核再完成 |
| 后续修订 | 里程碑核销/预算核销由负责人发起 | 预算核销改由二级单位财务上传付款凭证并本级核销，再同步 |
| 后续修订 | 项目负责人与项目联系人权限未完全对齐 | 项目负责人继承联系人全权限 |
| 后续修订 | 仅按系统菜单可见判断审核任务 | 审核任务应以待办中心（对应人员页面）为准 |

### 已确认实现并可复用的关键点

- 报备/状态非法跳转校验已加强。
- 财务提交与节点流转有接口层面状态保护。
- 基础待办弹窗、节点审核链路与消息推送顺序已开始实现。
- 关键回归场景：审批拒绝、退回重提、重复提交、无权限提交等存在测试脚本。

### 仍待核验的点

- 是否完全清除全部历史样本数据（排除旧数据污染）。
- 自动清理/清理无用服务版本文件在服务器上的执行闭环。
- 总体流程在无网络、重试、长链路超时时的幂等与一致性。
- 财务总核、年度预算联动与看板历史数据同步的边界一致性。
