# 接口清单

> 基础路径 `/api` · 认证方式 `Authorization: Bearer <token>`
> 统一响应体：`{ "code": 0, "msg": "ok", "data": ... }`（`code` 非 0 表示失败）
> 分页响应体：`{ "code": 0, "data": { "records": [], "total": 0, "page": 1, "size": 10 } }`

## 项目一本账 `projects`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/projects` | 分页查询，支持 keyword / levelCode / channelId / status / warnColor / orgId |
| GET | `/api/projects/{id}` | 详情（含参研单位、团队、年度计划） |
| GET | `/api/projects/{id}/overview` | **全周期详情聚合**（里程碑、计划、经费、评估、变更、验收、交付物、评价、转化、后评价） |
| POST | `/api/projects` | 新增，自动生成项目编号（仅管理团队 / 管理员） |
| PUT | `/api/projects/{id}` | 台账直接编辑（仅管理团队；项目团队须走基本信息审批草稿） |
| DELETE | `/api/projects/{id}` | 逻辑删除 |
| POST | `/api/projects/{id}/submit` | 提交备案（项目团队 / 单位管理团队） |
| POST | `/api/projects/{id}/refresh-status` | 重算四色状态（RED→DELAYED，恢复后回 IMPLEMENTING） |
| GET | `/api/projects/export` | 导出（与分页相同的数据范围） |
| PUT | `/api/projects/{id}/annual-plan` | 编制年度目标（只接受 year/annualGoal/planContent/dueDate，审核状态不可直写） |

### 项目基本信息审批草稿 `basic-draft`（实施阶段）

项目团队补充的基本信息先进草稿，节点：PROJECT_LEADER 项目负责人审核 → UNIT_TECH 单位科技管理部审核 → UNIT_LEADER 单位分管领导复核（团队未配置该岗位时自动跳过）→ HQ 总部科研项目处确认；全部通过后才写入 proj_info / proj_participant / proj_team_member。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/projects/{id}/basic-draft` | 当前草稿：status(NONE/DRAFT/APPROVING/APPROVED/REJECTED)、flowNode、flowNodes、payload、auditTrail、canEdit/canSubmit/canAudit |
| PUT | `/api/projects/{id}/basic-draft` | 保存草稿（项目团队；审批中不可改；字段白名单，系统字段被剔除） |
| POST | `/api/projects/{id}/basic-draft/submit` | 提交审批 |
| POST | `/api/projects/{id}/basic-draft/audit` | 当前节点审批 `{pass, opinion}`，末节点通过写台账 |
| GET | `/api/projects/basic-drafts/pending` | 当前登录人待审的草稿列表 |

## 里程碑 `milestones`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/projects/{id}/milestones` | 列表，可按 `year` 过滤，实时刷新四色；附 `dateLocked`、`canDelete`、`baselinePlanDate`、`delayCount`、`lagReason` |
| GET | `/api/milestones/board` | 填报看板（数据范围内）：summary / todos / projects |
| GET | `/api/milestones/mine` | 当前用户数据范围内的里程碑 |
| GET | `/api/milestones/{id}` / `/materials` | 详情、佐证材料（校验项目访问范围） |
| POST | `/api/milestones` | 新增 `{projectId,name,planDate,budget,year}`（计划日期须在项目周期内） |
| PUT | `/api/milestones/{id}` | 只接受 name/budget/year/planDate；状态、佐证、实际完成日期不可写；`dateLocked` 时改日期返回 400 |
| DELETE | `/api/milestones/{id}` | 逻辑删除，仅限 DOING、无佐证、未进基线的节点 |
| POST | `/api/milestones/{id}/materials` | 登记佐证 `{objectKey,fileName,fileUrl,fileSize}`，后端校验 MinIO 对象真实存在 |
| POST | `/api/milestones/{id}/lag` | 登记滞后原因 `{lagReason,lagMeasure}` |
| POST | `/api/milestones/{id}/delay` | 延期申请 `{newPlanDate,reason}` → 生成 MILESTONE_DELAY 变更单（返回 changeId），不直接改日期 |
| POST | `/api/milestones/{id}/close` | 销项申请 `{lagReason?,lagMeasure?}`：需真实佐证；逾期必填滞后原因；进入 CLOSE_DEPT_AUDIT |
| POST | `/api/milestones/{id}/close-audit` | 销项审核 `{pass,remark}`：项目承担部门负责人 → 单位科研管理部门负责人 → DONE/GREEN |
| POST | `/api/milestones/annual-plan/audit?projectId=&year=` | 年度清单审核 `{pass,remark}`；通过后固化各节点 `baselinePlanDate` |

## 变更 `changes`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/changes` | 分页，支持 projectId / changeType / status（按数据范围过滤） |
| GET | `/api/changes/{id}` | 详情（含 auditTrail） |
| POST / PUT `/{id}` / DELETE `/{id}` | `/api/changes` | 增删改：仅 DRAFT/REJECTED 且项目团队可改删（逻辑删除）；重大变更自动置 `legalReview` |
| POST | `/api/changes/{id}/submit` | 提交审批：项目变更 二级单位主管部门初审 → 总部对应管理部门终审 →（重大）法务；数据变更 二级单位内部审批 → 总部科技主管确认 |
| POST | `/api/changes/{id}/audit` | 当前节点审批 `{pass,opinion}`，逐节点推进；末节点通过 APPROVED 并生效（MILESTONE_DELAY 回写里程碑 plan_date、delayCount+1） |
