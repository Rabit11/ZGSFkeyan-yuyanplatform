# 数据库设计说明

> 数据库：阿里云 PolarDB（MySQL 8.0 兼容） · 字符集 `utf8mb4` / 排序规则 `utf8mb4_general_ci`
> 建表脚本：`backend/src/main/resources/db/schema.sql`

## 一、命名规范

| 前缀 | 业务域 | 示例 |
| --- | --- | --- |
| `sys_` | 系统域（组织、用户、角色、字典、预警、审计） | `sys_user`、`sys_dict` |
| `proj_` | 项目域（一本账、立项、实施、验收） | `proj_info`、`proj_milestone` |
| `fund_` | 项目级经费执行域 | `fund_budget`、`fund_payment` |
| `hq_` | 总部经费预算管控域 | `hq_fund_budget`、`hq_fund_transfer` |
| `achv_` | 成果转化域 | `achv_transform` |
| `biz_` | 通用审批流域 | `biz_flow_instance` |

金额字段统一 `DECIMAL(18,2)`，单位**万元**；日期 `DATE`，时间 `DATETIME`；
逻辑删除字段统一为 `deleted TINYINT DEFAULT 0`。

## 二、表清单（33 张）

### 1. 系统域

| 表名 | 说明 | 关键点 |
| --- | --- | --- |
| `sys_org` | 组织机构 | 总部 / 二级单位 / 部门 / 处室四级 |
| `sys_user` | 用户 | BCrypt 密码，含工号、所属组织 |
| `sys_role` | 角色 | `PROJECT_TEAM` / `CHIEF_ENGINEER` / `MANAGEMENT` / `FINANCE` / `ADMIN` |
| `sys_user_role` | 用户角色关系 | |
| `sys_dict` | 数据字典 | 按 `dict_type` 分组，支持 `parent_code` 级联 |
| `sys_warning` | 预警消息 | `YELLOW` 临期 / `RED` 逾期 |
| `sys_audit_log` | 审计日志 | 模块、动作、业务类型、操作内容 |

### 2. 项目渠道分类体系

| 表名 | 说明 |
| --- | --- |
| `proj_channel` | 15 个细分渠道：层级、渠道部委/司局、内部管理部门/处室、全周期流程节点、申报材料、立项材料 |

`proj_channel` 是全平台"差异化适配"的配置核心——前端据此**自适应展示附件填报栏目**，
非本渠道所需材料字段 `locked=1` 锁定不可编辑。

### 3. 项目一本账（主表 + 3 张子表）

| 表名 | 说明 |
| --- | --- |
| `proj_info` | 项目主表：编号、名称、目标、周期、层级、立项部门、渠道、牵头单位、状态、成果转化状态、四色预警、经费四列 |
| `proj_participant` | 参研单位（预留多个，含主要工作内容） |
| `proj_team_member` | 技术团队 / 责任专家 / 管理团队 / 财务团队共 12 类角色 |
| `proj_annual_plan` | 科研年度目标及计划 |

### 4. 立项阶段

| 表名 | 说明 |
| --- | --- |
| `proj_declaration` | 项目申报，含审批状态与当前节点 |
| `proj_filing` | 项目立项备案，备案后生成 `proj_info` |
| `proj_material` | 通用材料附件表（`biz_type` + `biz_id` + `field_code`），支持版本替换与 `locked` 锁定 |

### 5. 实施阶段

| 表名 | 说明 |
| --- | --- |
| `proj_milestone` | 年度里程碑：计划/实际完成时间、节点预算、四色状态、佐证标志、滞后原因 |
| `proj_plan` | CMOS 同步计划：待办 / 已完成、办结审批状态 |
| `proj_evaluation` | 评估检查：中期/季度/年度/阶段/督导，结论合格/不合格 |
| `proj_change` | 项目变更（`PROJECT`）与数据变更（`DATA`），含法务审核标志 |

### 6. 经费域（两套独立体系）

| 表名 | 体系 | 说明 |
| --- | --- | --- |
| `fund_budget` | 项目执行账 | 节点预算，绑定里程碑 |
| `fund_payment` | 项目执行账 | 付款/支出/核销流水，含凭证号与核销状态 |
| `hq_fund_budget` | 总部预算账 | 年度总盘子、锁定状态、审批状态 |
| `hq_fund_quota` | 总部预算账 | 各二级单位拨付额度上限与已用额度 |
| `hq_fund_transfer` | 总部预算账 | 拨付执行申请与双审状态 |

> **两套体系数据独立存储、互不联动**，与需求文档要求一致；所有经费操作全程留痕，支持审计溯源。

### 7. 验收阶段

| 表名 | 说明 |
| --- | --- |
| `proj_acceptance` | 验收主记录：层级、状态、责任总师技术复核标志、协作单位评价到期日 |
| `proj_acceptance_item` | 分级材料栏：`UNIT` / `COMPANY` / `NATIONAL` / `LOCAL`，非对应层级 `locked=1` |
| `proj_deliverable` | 交付物：类型、应交付/实际交付、权属、关联成果编号 |
| `partner_eval` | 协作单位评价：5 维度各 20 分、总分、等级 |
| `partner_blacklist` | 不合格协作单位黑名单 |

### 8. 成果转化与后评价

| 表名 | 说明 |
| --- | --- |
| `achv_transform` | 成果包：成果编号（全局唯一）、转化方式/形式、计划与实际转化时间、四色状态 |
| `achv_transform_item` | 成果包与交付物绑定关系（`transform_id` + `deliverable_id` 唯一） |
| `proj_post_eval` | 后评价：6 个评价维度、综合评分、结论 |

### 9. 通用审批流

| 表名 | 说明 |
| --- | --- |
| `biz_flow_instance` | 流程实例：`biz_type` + `biz_id` 关联各业务单据 |
| `biz_flow_task` | 审批任务节点：节点名、顺序、处理人、动作、意见 |

## 三、核心关系

```
proj_channel 1 ── n proj_info（渠道分类）
proj_info    1 ── n proj_participant / proj_team_member / proj_annual_plan
proj_info    1 ── n proj_milestone / proj_plan / proj_evaluation / proj_change
proj_info    1 ── n fund_budget / fund_payment
proj_info    1 ── 1 proj_acceptance ── n proj_acceptance_item
proj_info    1 ── n proj_deliverable
proj_info    1 ── n partner_eval
proj_info    1 ── n achv_transform ── n achv_transform_item ── n proj_deliverable
proj_info    1 ── 1 proj_post_eval
proj_declaration 1 ── 1 proj_filing ── 1 proj_info（备案生成项目）
hq_fund_budget 1 ── n hq_fund_quota 1 ── n hq_fund_transfer
```

## 四、关键字段口径

| 字段 | 口径 |
| --- | --- |
| `proj_info.status` | 由系统根据项目进展自动归集生成，无需手工填报 |
| `proj_info.transform_status` | 由成果转化台账数据自动归集生成 |
| `proj_info.warn_color` | 取里程碑、交付物、待办计划中最严重的四色状态 |
| `proj_deliverable.achievement_no` | 交付物与成果转化的**联动主键**，多项交付物可绑定同一成果编号实现打包转化 |
| `achv_transform.achievement_no` | 系统自动生成的全局唯一标识 |
| `proj_material.locked` | `1` = 当前渠道不适用，前端锁定不可编辑 |
| `proj_change.legal_review` | `1` = 重大变更，强制联动法务部门审核 |

## 五、四色预警规则

| 颜色 | 编码 | 触发条件 |
| --- | --- | --- |
| 绿 | `GREEN` | 已完成并审核通过 |
| 蓝 | `BLUE` | 距到期 > 30 天 |
| 黄 | `YELLOW` | 距到期 ≤ 30 天（到期前 30 天自动触发预警） |
| 红 | `RED` | 已超期（到期当日触发，台账与看板高亮） |

后端统一由 `com.comac.rpm.common.util.ColorUtil#calc(LocalDate, boolean)` 计算，
前端由 `frontend/src/utils/color.ts#calcColor` 镜像实现，两端规则一致。
