# 科研项目信息化管理平台人员角色权限与节点权限说明

## 1 文档目的

本文依据《科研项目信息化管理平台需求 V19.1》整理平台人员角色、数据范围、功能权限和流程节点权限，用于指导产品设计、权限配置、接口校验、待办分发和验收测试。

权限控制应同时满足四项条件：

1. 登录人员具备相应平台角色；
2. 登录人员处于该项目允许的数据范围内；
3. 登录人员是当前项目相应岗位绑定的具体人员；
4. 业务状态和当前流程节点允许执行该操作。

仅有菜单访问权、项目查看权或相同岗位身份，均不代表可以代替当前节点指定人员办理审批。

## 2 权限术语

| 权限类型 | 说明 |
|---|---|
| 查看 | 查看职责范围内的项目、字段、材料、流程、审批意见和归档信息，不包含修改权 |
| 填报 | 新建或补充业务字段、上传附件、维护尚未提交的业务数据 |
| 编辑 | 修改尚未锁定的数据；已审批生效的数据原则上通过项目变更或数据变更流程调整 |
| 提交 | 将草稿送入审批、备案或办结流程，并生成下一节点待办 |
| 审批 | 当前节点指定人员执行通过或驳回，并填写审批意见 |
| 备案 | 对已完成审批的资料进行登记、确认和归档，不得替代业务审批 |
| 导出 | 按角色和数据范围导出项目台账或统计数据 |
| 运维配置 | 维护账号、角色、权限矩阵、流程模板、渠道字典和表单配置，不直接修改业务事实 |

## 3 权限判定原则

### 3.1 指定到人

申报阶段填写的岗位人员应保存姓名和工号。流程发起时，每个需要人工办理的节点必须解析到具体人员；待办、红点数量、审批详情和接口校验均使用同一人员绑定关系。

人员匹配以工号为主、姓名为辅助。存在同角色多人时，只有当前项目所指定的人员可以办理，不得仅凭角色名称放行。

### 3.2 数据范围

| 数据范围 | 适用人员 | 范围说明 |
|---|---|---|
| 全公司 | 总部管理团队、公司领导、超级管理员及按职责授权的总部财务人员 | 查看全公司或总部责任范围内项目；导出权按具体角色控制 |
| 本单位 | 二级单位管理团队、二级单位财务团队 | 查看本单位所属项目及本单位负责的待办 |
| 本人经手 | 项目团队、一级总师、二级总师、评审人员 | 查看本人在项目岗位、审批节点或评审任务中被明确关联的项目 |
| 专项业务 | 财务、评审、成果转化等专业岗位 | 仅查看职责需要的业务模块及相关字段，不自动获得项目源数据修改权 |

### 3.3 状态限制

- 草稿状态允许具备填报权的人员编辑和提交。
- 审批中仅允许当前节点指定人员审批；其他人员只读。
- 驳回后退回初始填报节点，由原填报责任人补正并重新提交。
- 已审批数据原则上锁定；修改关键字段必须发起项目变更或数据变更。
- 已验收、已归档数据原则上只读。
- 撤销仅允许流程填报人发起，撤销记录永久留存。
- 流程中的经办人或审核人可按需求规则替换附件，所有版本和操作均应留痕。

## 4 人员角色权限

### 4.1 项目团队

| 项目岗位 | 主要职责 | 填报与提交权限 | 查看范围 | 限制 |
|---|---|---|---|---|
| 项目联系人 | 组织申报材料、维护沟通信息、协助全周期材料归集 | 发起项目申报；上传或补正申报材料；按节点协助填报实施和验收材料 | 本人关联项目 | 不得代替项目负责人、总师、管理或财务人员审批 |
| 项目负责人 | 对项目目标、进度、经费、验收和成果转化总体负责 | 审核项目申报；提交项目基本信息、验收申请及职责范围内的业务；配合成果转化信息填报 | 本人负责或经手项目 | 项目团队其他人员提交的项目事项按流程交由项目负责人审核；不得越过后续管理审批 |
| 技术负责人 | 负责技术方案、年度目标、里程碑、交付物和技术材料 | 填报里程碑、技术交付物和技术佐证材料；按授权提交技术事项 | 本人关联项目 | 不得办理财务、管理或总师审批节点 |
| 项目主管 | 协助项目计划、过程检查和日常推进 | 填报计划、评估检查、变更等过程信息；按授权提交办结申请 | 本人关联项目 | 不得代替项目负责人承担最终项目责任 |

项目团队只能查看和操作本人关联项目，在提交保存前可编辑本人负责内容，无全量数据导出权限。

### 4.2 责任总师

| 角色 | 主要职责 | 节点权限 | 查看范围 | 限制 |
|---|---|---|---|---|
| 一级总师 | 公司级技术指导和技术把关 | 办理申报、验收、评估等流程中配置的一级总师节点 | 本人经手的全部项目 | 原则上无项目业务数据直接修改权 |
| 二级总师 | 单位级技术指导和技术把关 | 办理申报、验收、评估等流程中配置的二级总师节点 | 本人经手的全部项目 | 只审核本项目申报时指定给本人的节点，不得审核其他二级总师任务 |

责任总师可以查看待审材料、历史审批意见和本人经手项目，不直接修改项目团队提交的业务事实。

### 4.3 管理团队

| 角色 | 主要职责 | 节点权限 | 查看范围 | 限制 |
|---|---|---|---|---|
| 总部责任处室处长 | 负责总部层面的项目统筹、审批和督办 | 办理总部责任部门审批、终审或备案节点 | 全公司或责任处室项目 | 不直接修改项目源数据 |
| 总部责任处室主管 | 负责总部日常管理、材料核验和流程协同 | 办理总部主管审核、材料核验和备案任务 | 全公司或责任处室项目 | 不能代替处长办理明确指定给处长的节点 |
| 单位科技部长 | 负责本单位科研项目管理和内部审批 | 办理单位科技部门负责人、单位管理团队审核等节点 | 本单位项目 | 不直接覆盖已审批业务数据 |
| 单位科技主管 | 负责本单位项目日常管理、过程检查和材料核验 | 办理单位科技主管、计划办结、评估检查等配置节点 | 本单位项目 | 不能代替部长或分管领导审批 |
| 单位分管领导 | 负责单位级管理复核 | 办理项目申报和项目基本信息流程中的单位分管领导节点 | 本单位经手项目 | 必须单独配置具体姓名和工号，不得由单位科技部长默认代办 |

管理团队可以组织协作单位评价和成果转化审核。需求中的“无修改权限”应解释为不得直接修改项目团队提交的项目源数据；其在指定业务节点录入审核意见、评价结论和备案结果属于流程办理权限。

### 4.4 财务团队

| 角色 | 主要职责 | 节点权限 | 查看范围 | 限制 |
|---|---|---|---|---|
| 总部财务主管 | 总部经费统筹、预算复核、异常监管和拨付核对 | 办理总部财务复核备案、总部拨付审核和异常核查节点 | 总部职责范围内经费数据 | 不修改科研业务内容和二级单位原始凭证 |
| 单位财务部长 | 本单位预算审核、经费核对和核销管理 | 办理单位财务部门负责人审核；里程碑闭环后组织核销 | 本单位项目经费 | 不直接修改项目技术和管理信息 |
| 单位财务主管 | 经费经办、凭证上传和数据核对 | 按授权上传付款凭证、补充核销材料和协同核查 | 本单位项目经费 | 无项目源数据修改权；是否具有最终审核权由流程配置决定 |

里程碑全部完成并通过审核后，由二级单位财务上传付款凭证或核销材料，完成本级核销，系统将项目经费执行和结余数据同步至总部经费看板。

### 4.5 其他角色

| 角色 | 主要职责与权限 | 主要限制 |
|---|---|---|
| 评审人员 | 在受邀评审阶段查看指定项目材料并提交评审意见 | 仅限被分配的评审项目和评审时段 |
| 公司领导 | 查看公司级项目态势、台账、风险和统计分析 | 原则上只读，不参与日常填报和普通审批 |
| 超级管理员 | 维护账号、权限、渠道字典、流程模板和表单；完成平台运维与审计；在立项流程全部审批完成后登记立项或不立项结果 | 禁止直接修改业务数据，不应常态替代业务人员审批 |

## 5 项目申报阶段节点权限

### 5.1 通用申报规则

- 项目团队填报申报信息并上传渠道要求材料。
- 项目负责人提交申报时，仍需完成项目负责人审核节点。
- 项目团队其他人员提交时，流程首先传递给申报时指定的项目负责人。
- 每次审批通过后只生成下一节点指定人员的待办；审批完成后进入“我的已办”。
- 审批驳回后自动退回初始填报节点，并保存驳回意见和历史记录。
- 无需审批的报备类项目由各单位科技部门审批后自动归档，总部可查询追溯。

### 5.2 常规渠道审签链

适用于 MJKY、04 专项接续、重点研发计划、国家自然科学基金、揭榜挂帅、科技创新行动计划、预研三年滚动计划和新疆大飞机气象创新中心：

| 顺序 | 流程节点 | 指定人员来源 | 节点操作 |
|---:|---|---|---|
| 1 | 项目联系人填报 | 申报岗位中的项目联系人 | 填写、上传材料、提交、撤销、驳回后补正 |
| 2 | 项目负责人审核 | 申报岗位中的项目负责人 | 查看全部申报信息和材料，审批通过或驳回 |
| 3 | 项目承担部门负责人审核 | 申报岗位中的项目承担部门负责人 | 部门审核，通过或驳回 |
| 4 | 二级总师审核 | 申报岗位中的二级总师 | 技术审核，通过或驳回 |
| 5 | 单位财务部门负责人审核 | 申报岗位中的单位财务部长 | 经费审核，通过或驳回 |
| 6 | 单位科技部门负责人审核 | 申报岗位中的单位科技部长 | 管理审核，通过或驳回 |
| 7 | 单位分管领导审核 | 申报岗位中单独配置的单位分管领导 | 单位复核，通过或驳回 |
| 8 | 一级总师审核 | 申报岗位中的一级总师 | 公司级技术审核，通过或驳回 |
| 9 | 总部科技部科研项目处审核 | 按渠道归口到总部责任处室处长或主管 | 总部审核，通过或驳回 |
| 10 | 立项结果登记 | 超级管理员或明确授权的结果办理人 | 登记立项或不立项，归档结果 |

XX25 专项不包含单位财务部门负责人节点，其余节点按上表执行。

### 5.3 特殊渠道节点

| 项目渠道 | 审批或办理链 | 权限说明 |
|---|---|---|
| 科技周 | 项目负责人 → 三级专业总师 → 二级专业总师 → 单位科技部 → 单位科技部门负责人 → 单位分管科技领导 → 总部科技部科技发展处 → 一级总师 → 总部科技管理部 → 需求发布 → 技术发展战略委员会审查 → 拟立项清单发布 | 专业总师、委员会和发布节点需独立配置人员或人员组 |
| 大飞机研究院 | 建设单位征集指南 → 学术委员会评审 → 指南发布 → 项目建议书形成 → 学术委员会评审 → 拟立项清单 → 理事会审议 → 研究院立项 | 委员会和理事会节点属于组织型评审，应记录评审成员和意见 |
| 大飞机先进材料创新联盟 | 联盟成员单位提交申请书 → 联盟专委会审查 → 联盟理事会审查 → 公司科技部报批 | 专委会、理事会和公司科技部应分别配置办理人员或人员组 |
| 中国商飞 波音可持续航空技术研究中心项目 | 项目负责人 → 北研中心科技部主管 → 北研中心科技部部长 → 北研中心分管领导 → 总部科技部主管 | 以申报时或渠道模板中指定的具体人员为准 |

## 6 立项备案和实施阶段节点权限

| 模块 | 填报或发起人员 | 审批或确认人员 | 完成后的系统动作 |
|---|---|---|---|
| 项目立项 | 项目团队上传任务书、立项批复、批准通知等渠道材料 | 总部归口管理人员备案 | 形成正式项目并进入实施阶段，申报岗位同步为项目团队岗位 |
| 项目基本信息 | 项目团队补充立项阶段缺失字段 | 项目负责人 → 单位科技管理部 → 单位分管领导 → 总部科研项目处 | 审批通过后更新项目台账 |
| 年初里程碑清单和节点预算 | 项目团队填报年度目标、里程碑和预算 | 二级单位科技部门审核存档 | 形成年度目标、里程碑和交付物基线 |
| 里程碑完成和佐证材料 | 项目团队上传试验、验收等完成材料 | 二级单位内部核验 | 节点闭环销项并转为绿色；延期必须走项目变更 |
| 计划管理 | CMOS 自动同步计划；项目团队提交办结申请 | 二级单位管理团队终审 | 计划进入已完成列表 |
| 经费预算 | 项目团队按里程碑填报 | 二级单位财务部门 → 总部财务团队复核备案 | 预算生效并进入经费台账 |
| 经费核销 | 里程碑闭环后由二级单位财务上传付款凭证或核销材料 | 二级单位财务完成本级核销；异常由两级财务联合核查 | 同步项目经费执行、结余和总部经费看板 |
| 评估检查 | 项目团队按渠道填报评估或检查材料 | 二级单位主管部门初审 → 总部对应管理部门终审；部分渠道仅二级单位确认 | 归档评估结论；不合格项目进入整改 |
| 项目变更 | 项目团队填报变更内容、原因和佐证 | 二级单位主管部门初审 → 总部对应部门终审；重大变更增加法务审核 | 审批通过后更新受控项目数据 |
| 数据变更 | 项目团队填报小范围数据纠错 | 二级单位内部审批 → 总部科技主管确认 | 更新对应字段并保留变更记录 |

## 7 验收 成果与后续节点权限

| 模块 | 填报或发起人员 | 审批或确认人员 | 关键约束 |
|---|---|---|---|
| 项目验收 | 项目团队发起并上传分级验收材料 | 二级单位管理团队初审 → 国家级或 MJKY 项目增加责任总师技术复核 → 总部管理团队终审 | 全部里程碑闭环、外协交付物验收合格、节点经费核销完成后才可提交 |
| 交付物 | 项目团队按任务书逐项填报和更新 | 二级单位管理团队 → 总部管理团队 | 核心交付物全部为已交付后才能申请验收 |
| 协作单位评价 | 项目团队填报基础信息并参与五维评分 | 二级单位管理团队 → 总部管理团队 | 参研单位在项目验收后 30 日内评价；外协单位在合同验收后 30 日内评价 |
| 成果转化 | 项目团队填报或更新成果包、转化进度和佐证材料 | 二级单位管理团队审核确认 → 总部管理团队备案 | 仅已交付成果可纳入成果包；数据同步项目台账与看板 |

| 项目申报 | 本人项目 | 本人经手或待审项目 | 本单位项目 | 责任范围项目 | 当前财务待审项目 | 按授权只读 | 全量运维查看 |
| 项目立项 | 本人项目 | 本人经手项目 | 本单位项目 | 全公司或责任范围 | 本单位或总部经费相关项目 | 按授权只读 | 全量运维查看 |
| 实施与验收 | 本人项目 | 本人经手项目 | 本单位项目 | 全公司或责任范围 | 经费及验收相关项目 | 按授权只读 | 全量运维查看 |
| 成果转化 | 本人项目 | 本人经手项目 | 本单位项目 | 全公司或责任范围 | 按授权查看 | 按授权只读 | 全量运维查看 |
| 数据导出 | 无全量导出 | 原则上无全量导出 | 按授权导出本单位 | 允许职责范围导出 | 按财务职责导出 | 按授权 | 按运维授权 |

## 9 待办 已办与审计要求

1. 当前节点产生后，待办必须发送给该节点绑定的具体工号。
2. 左侧菜单和消息中心显示本人待办数量，并可进入对应项目、节点和材料详情。
3. 审批完成后，任务从“待我审核”移入“我的已办”，保留项目名称、流程类型、办理节点、审批结果、意见和办理时间。
4. 流程参与人员可以查看其权限范围内的历史审批轨迹；未经授权人员不得通过项目编号绕过数据范围查看详情。
5. 提交、审批、驳回、撤销、转办、附件替换、备案和业务数据回写均记录操作者姓名、工号、时间、节点和结果。
6. 人员岗位调整后，应回收原人员后续办理权限，并按正式转办或岗位变更记录移交未完成任务。

## 10 申报人员与后续流程对齐规则

申报阶段是项目全生命周期人员信息的权威来源。立项备案完成后，系统应将申报人员按岗位编码同步到项目团队，并遵循以下规则：

| 申报岗位 | 后续主要填报或审批职责 |
|---|---|
| 项目联系人 | 申报材料组织、流程协同、部分材料补充 |
| 项目负责人 | 申报负责人审核、项目基本信息确认、验收发起、项目总体事项 |
| 技术负责人 | 年度目标、里程碑、交付物和技术佐证 |
| 项目主管 | 计划、评估、变更和日常过程管理 |
| 一级总师 | 公司级技术审核和国家级重大项目验收复核 |
| 二级总师 | 单位级技术审核和本人经手项目技术把关 |
| 项目承担部门负责人 | 申报承担部门审核 |
| 单位科技部长 | 单位科技部门审核、单位管理确认 |
| 单位科技主管 | 单位日常管理、计划和评估办理 |
| 单位分管领导 | 单位管理复核 |
| 总部处室处长 | 总部责任部门审批或终审 |
| 总部处室主管 | 总部材料核验、管理审核和备案办理 |
| 单位财务部长 | 单位预算和经费审批 |
| 单位财务主管 | 凭证上传、核销经办和数据核对 |
| 总部财务主管 | 总部预算复核、异常监管和拨付核对 |

禁止在后续流程中使用与申报岗位无关的固定人员或仅凭身份代码随机匹配审批人。确需更换人员时，应通过项目岗位变更或任务转办完成，并保存前后人员及操作记录。

## 11 需求缺口与配置要求

根据 V19.1 文档，系统落地时应特别处理以下事项：

1. 标准申报审签链包含“单位分管领导”，但项目团队字段表未列出该字段，系统应补充单位分管领导姓名和工号，或由渠道流程模板明确其人员来源。
2. 项目联系人出现在申报链中，但项目台账团队字段未列出项目联系人；申报和待办仍应保留该岗位，是否同步到项目台账由产品配置确定。
3. 评审团队在项目申报查看角色中出现，但角色定义表未明确成员范围，应配置评审任务、有效期和数据隔离规则。
4. 管理团队和财务团队的“无修改权限”指无权直接修改项目源数据，不影响其在指定节点填写审核意见、评价结果、核销材料或备案结果。
5. 超级管理员可登记最终立项结果，但不得直接更改项目申报、经费、验收等业务内容。
6. 特殊渠道中的学术委员会、理事会、专委会、技术发展战略委员会等组织型节点，应配置人员组、会签规则、最低通过条件和意见归档要求。

## 12 验收检查清单

- [ ] 申报时所有必需岗位均保存姓名和工号。
- [ ] 每个审批节点均可解析到具体人员或明确的组织型评审组。
- [ ] 当前节点人员能在“待我审核”看到任务和红点提示。
- [ ] 非当前节点人员即使具有相同身份也不能审批。
- [ ] 审批通过后任务进入“我的已办”，下一节点正确收到待办。
- [ ] 驳回后由原填报责任人补正，历史意见和附件版本可追溯。
- [ ] 立项后人员信息完整同步到项目团队和后续流程。
- [ ] 实施、经费、验收和成果转化节点均使用项目绑定人员，不使用固定姓名。
- [ ] 单位、总部、本人经手等数据范围在列表、详情和附件接口保持一致。
- [ ] 已审批和已归档业务数据不能通过普通编辑接口绕过变更流程。
- [ ] 所有提交、审批、驳回、撤销、转办和业务回写均有审计记录。

## 13 依据与适用说明

本文依据《科研项目信息化管理平台需求 V19.1》中的角色定义、功能架构、项目申报审签流程、实施阶段审批流、验收流程和成果转化流程整理。不同项目渠道存在差异化节点时，以该渠道经审批发布的流程模板为准；流程模板不得突破本文规定的数据范围、指定到人、状态校验和审计留痕原则。
