# 导入补录信息入库与台账、大屏同步说明

日期：2026-09-15

## 数据与展示规则

- 草稿、附件元数据、提交快照和审核记录分别存储在 `proj_supplement_section`、`proj_supplement_file`、`proj_supplement_history`；附件内容保存在 MinIO。
- 提交后，台账和领导大屏显示“待审核”，可以查看已提交信息、附件、办理人、时间和审核意见。
- 审核状态与项目业务状态分开：待补录、待审核、已退回、部分通过、已通过；项目仍保留实施中等原业务状态。
- 待审核内容不作为已审核统计。已有审核通过版本时，新批次草稿、退回后的修改和新提交不会覆盖上一版已通过信息。
- 已审核基本信息、经费、里程碑、交付物和成果转化通过共同的展示计算逻辑进入台账、大屏。补录完整栏目替换该项目同类统计集合，避免将原有业务记录重复计数。
- 经费表中重复填写的总预算只取一致值，不累加；支出与核销分开，核销不再次计入支出。不一致的总预算保留原口径并提示核对。
- 不通过补录审核改写业务流程表或改变项目生命周期；以数据库中的不可变审核快照提供查询视图。

## 权限

| 人员 | 查看范围与操作 |
| --- | --- |
| 项目负责人 | 保留原补录入口中的保存、上传、提交、新建批次权限 |
| 单位及总部审核人员 | 按原审核节点办理；不能修改负责人补录内容 |
| 领导 | 查看权限范围内项目的已提交信息、已审核版本和审核情况；不能修改、提交或审核 |
| 原项目成员 | 查看本人关联项目的已提交内容和附件 |
| 审核通过的补录团队成员 | 按精确工号建立只读项目关联；不授予负责人或审核权限 |
| 无关人员 | 不能通过指定项目 ID、附件 ID 或单位筛选绕过项目范围 |

后续未提交草稿仅原负责人和具备原补录查看权限的管理、审核人员可见；公开只读接口只返回提交、通过、退回事件的快照。

## 页面

- 项目台账：保留业务状态，增加补录审核状态筛选、查看审核入口；筛选后的项目数量、经费汇总保持一致。
- 领导大屏：增加导入项目补录列表，显示待审核、退回、通过情况；项目范围跟随现有大屏筛选。
- 查看抽屉：已提交信息与材料、审核情况、已审核版本。仅查看、下载与刷新，没有上传或修改入口。
- 页面可见且未打开编辑或审核查看抽屉时，每 30 秒刷新；重新聚焦页面也刷新。查看抽屉提供手动刷新，避免阅读时内容跳变。
- 上传入口仍在左侧“导入项目补录”。项目详情三阶段节点保持只读，不增加审批流程图。

## 已完成的验证

- 后端专项：补录快照、补录校验、渠道清单、模板配置、项目访问权限测试通过。
- 前端：生产构建、三阶段展示回归、补录统计去重、经费核销不重复计支出、大屏筛选范围回归通过。
- 隔离数据库接口：保存入库、草稿不可见、提交同步、退回意见、单位审核、总部审核、新批次保留已审核版本通过。
- 权限接口：原项目成员可见、单位筛选不扩大范围、领导只读、成员不能审核、已审核团队工号关联通过。
- 附件接口：草稿附件拒绝访问、已提交附件可下载通过。
- 浏览器：领导大屏、领导与成员台账、审核意见、只读材料抽屉通过。

本次验证针对补录同步链路，不等同于整份需求说明书的全量验收。原成果转化集成测试中的已知基线失败不纳入本次通过结论。
