本次只检查“项目申报”和“立项备案”，没有修改其他业务模块。

## 自动测试

脚本：`qa/mock-declaration-approval-flow.mjs`

执行：

```bash
node qa/mock-declaration-approval-flow.mjs
```

测试行为：

1. 自动读取 Mock 中全部 `declarations`，当前共 5 条，不写死项目 ID。
2. 临时补齐渠道必传材料，登录项目联系人并提交申报。
3. 依次登录项目负责人、项目承担部门负责人、二级总师、单位财务部门负责人、单位科技部门负责人、单位分管领导、一级总师、总部科研项目处。
4. 每个节点调用 `/api/declarations/pending`，断言指定账号能看到当前项目。
5. 使用无关账号反向断言当前项目不会出现在其待办中。
6. 调用审核接口推进下一节点，最终断言状态为 `APPROVED`、节点为“归档”。
7. 测试结束恢复申报、材料和登录状态，不污染 Mock 数据。

## Mock 覆盖边界

Mock 项目台账样本很多，但“项目申报”演示数据目前只有 5 条；这 5 条覆盖 MJKY、04 专项接续、预研三年滚动计划、重大科技创新专项、重点研发计划。它们没有覆盖 `XX25`、科技周、大飞机研究院、先进材料创新联盟、商飞-波音中心项目及无需审批报备样本，因此不能替代这些渠道的需求验收。

## 建议的后续修复范围

如继续修复，仍应限制在项目申报、立项备案：按渠道配置可执行审批链；为无需审批项目增加“单位科技部审批→自动归档”链路；补齐特殊渠道材料字段；实现真实转办接口、权限校验和审计留痕；再补充对应渠道的 Mock 样本和自动化测试。
