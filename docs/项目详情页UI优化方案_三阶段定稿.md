# 项目详情页 UI 优化方案（三阶段定稿）

日期：2026-09-15  
状态：用户已确认的最终设计方案；实现及上线状态须另行验收。

## 0. 用户最终确认口径（2026-09-15）

本节为最终实施边界，以现有截图布局为基础。

| 区域 | 最终设计 |
|---|---|
| 顶部信息区 | 保留现有布局，用一个小标签区分“平台立项／表单导入”；保留摘要及统计位置 |
| 生命周期区 | 立项备案 → 实施阶段 → 验收转化；按来源渠道展示阶段状态、已有材料和后续材料要求，节点仅供查看 |
| 下方详情区 | 保留现有标签页顺序、展示方式和内部布局，仅移除“补录归集”，默认显示“概览” |

固定标签顺序：**概览｜里程碑｜计划｜经费｜交付物｜协作评价｜成果转化｜审批与归档｜项目可视化**。

补录信息和附件归入对应业务标签及阶段材料清单供查看，不删除历史数据。导入项目上传、提交统一从左侧“导入项目补录”进入；平台立项项目通过左侧对应业务功能办理。详情页只提供查看、预览和下载，不打开审批链、流程图或逐节点轨迹。

截图中概览区域的“待维护项目材料”大块拆解为对应业务信息和附件；上传、提交单位审核按钮及三段审批人员流程卡片移出详情页。“审批与归档”保留结果及文件，“项目可视化”保留进度、经费和成果视图。这是只读边界的落实，不重新设计九个标签页。

### 达索材料包应用原则

参考本地材料索引中的统一产品壳层、对象工作区、高密度分区和渐进展开方式。保留现有蓝色顶栏、左侧导航、项目头部和业务标签；三阶段等宽紧凑排列，阶段材料按需展开，展开时不改变业务标签选择。材料包提出的三栏骨架和右侧审批面板不纳入本次设计；用户确认的布局优先。尺寸与配色复用平台变量，本文件建议值不代表达索官方规范。

### 交付状态

本次交付为最终方案文档，不表示代码已实现或服务器已更新。验收覆盖两种建立方式、不同渠道、历史缺项、未来材料、未知渠道、空数据、多版本文件及访问权限，详细清单见第10节。

## 1. 最终设计结论与范围

项目详情页采用“现有项目信息头部 + 三阶段生命周期 + 现有业务标签页”。用户进入页面后，可以查看项目当前状态、责任人、已上传的详细信息与材料，以及按渠道流程后续需要准备的材料。

本版明确采用以下口径：

1. 生命周期统一为 **立项备案 → 实施阶段 → 验收转化**。
2. 顶部仅用一个小标签区分 **平台立项 / 表单导入**，两类项目共用页面布局及材料展示规则。
3. 根据“项目来源/渠道”匹配流程及材料要求；建立方式不决定材料清单。
4. 下方保留现有标签页结构及内容布局，**仅移除“补录归集”标签页**，默认选中“概览”。
5. 补录的数据与附件归入对应业务标签供查看，移除标签不删除数据、不移除左侧补录功能。
6. 流程节点及详情页只提供查看、预览、下载；填报、上传、提交、审核办理统一从左侧相应功能栏进入。
7. **本页不打开或展示审批流转流程图、审批链、节点流转轨迹**。移除“审批流转”“实施流转”“验收流转”等入口；生命周期只展示阶段摘要及材料，不打开原有流程弹窗。

本文件替代《项目台账与经费流程UI优化方案》中关于详情页六类重新分组、详情页“进入办理”、四/五阶段生命周期的早期设计口径。台账列表及其他模块不在本次页面改版范围内。

阶段明细默认收起；用户选择阶段后在生命周期区域内展开，再次点击可收起。展开阶段不切换下方业务标签，不重置下方已选标签。

阶段卡片原“查看详情”统一改为“查看材料”，明确查看对象；点击后仅展开材料清单及提交要求，不调用审批流转、实施流转、验收流转弹窗或抽屉。

## 4. 项目信息头部与建立方式标签

沿用现有头部布局，仅收敛建立方式的显示文案：平台创建显示“平台立项”，表单维护导入显示“表单导入”。标签放在项目名称/状态附近，同一位置、同一尺寸，不增加第二套来源说明大卡片。

- **建立方式**：平台立项或表单导入，用于追溯数据来源。
- **项目来源/渠道**：MJKY、04 专项接续等业务渠道，用于确定流程、阶段要求及材料清单。
- 两类字段独立，不能用“表单导入”替代业务渠道。
- 建立方式根据项目创建/导入记录识别，不能凭是否有附件或是否完成审批推断；未知时显示“来源待确认”。
- 项目运行状态与资料补齐状态独立，不因缺材料将已完成项目改为未开始。

## 5. 三阶段生命周期

### 5.1 阶段对应关系

| 展示阶段 | 归入的业务环节 | 卡片摘要 |
|---|---|---|
| 立项备案 | 项目申报、立项备案 | 申报/备案当前环节、完成状态、应交材料缺项 |
| 实施阶段 | 基本信息、团队、里程碑、计划、经费、评估检查、项目变更等渠道适用环节 | 当前事项、责任人、应交材料、风险提示 |
| 验收转化 | 项目验收、成果转化 | 验收与转化分别所处状态、材料准备要求 |

“项目完成归档”不再作为独立生命周期阶段。下方“审批与归档”标签继续保留。展示阶段合并不改变后台实际审批顺序和原有业务状态。

### 5.2 卡片内容与状态

三个卡片等宽、同高，单层结构，通过细连接线/箭头表达顺序，移除内部子卡片和重复的阶段编号。

每张卡片展示：阶段名称、业务状态、材料齐备情况，以及一条最相关的事项/责任人摘要。多条任务显示首条摘要及“另有 N 项”，完整内容在阶段明细查看。

- 业务状态：未开始、办理中、已完成；异常或退回状态按真实业务记录显示。
- 材料状态：齐备、待补充、待审核、已退回、后续需提供，不能与业务状态混为一项。
- 当前业务阶段用蓝色标识；历史完成阶段可同时显示“已完成 · 缺 3 项材料”。
- 卡片选中态使用细边框/底部标记，与“当前阶段”文字区分；查看历史阶段不改变当前阶段。
- 验收完成但转化仍待办理时，展示“验收已完成 · 转化待办理”，不能将整个阶段标为完成。
- 渠道配置不要求转化时，明确“转化不适用”，不虚构待办。
- 导入项目仅使用有依据的业务状态；无法判断时显示“阶段待确认”，不制造审批完成记录。

### 5.3 阶段只读明细

明细头部显示当前事项、办理角色/人员、截止时间、风险及办理位置文字。没有指定人员时显示“待指定”，不能默认将项目负责人认定为审核人。

下面使用紧凑的材料列表，筛选为“全部 / 已上传 / 待补充 / 后续需提供”。列项如下：

| 列项 | 内容 |
|---|---|
| 环节 / 材料名称 | 渠道配置对应环节与标准材料名称 |
| 要求 | 必填或条件适用，以及条件说明 |
| 提交时机 | 具体业务触发条件或已配置截止日期 |
| 状态 | 未上传、已上传待审、审核通过、已退回、后续需提供、不适用 |
| 文件信息 | 文件名、版本、上传人、上传时间；多文件可展开 |
| 责任人 | 应补充材料的责任角色及已指定人员 |
| 操作 | 查看详情、预览、下载，受访问权限控制 |

“下一步去哪办”以文字路径提示，例如“办理位置：左侧【导入项目补录 → 我的补录】”。不提供从流程节点直接进入上传、填报或审核的按钮。

### 5.4 审批流转展示边界（本次补充）

- 生命周期保留三个阶段及当前状态、当前事项/责任人、风险和材料摘要，不展示“下一流程：某部门 → 某人员”等流转链。
- 移除概览中项目团队区域的“审批流转”“实施流转”“验收流转”链接，以及本页其他打开同类流程的入口。
- 不通过弹窗、抽屉、内嵌图或新标签页从本页打开审批链、审批节点轨迹、流程办理详情。
- 保留材料自身的审核状态及已形成的审批结果文件，供预览和下载；这不包含流程图或逐节点审批历史展示。
- 详细审批流转信息统一在左侧对应业务模块或待审/已办页面查看，本页仅提示功能栏位置。
- 上述限制适用于整个详情页，包括“审批与归档”和“项目可视化”，不能通过下方标签重新打开审批流转图。

## 6. 渠道材料识别和统计

材料要求由“项目来源/渠道 + 适用流程版本 + 业务环节 + 条件规则”确定，统一用于平台立项项目和表单导入项目。

1. 使用渠道字典的稳定标识匹配配置，展示名称仅用于界面阅读。
2. 明确展示当前使用的渠道及规则版本；渠道缺失、未知或无配置时显示“材料要求待确认”，不回退套用其他渠道清单、不显示虚假的 100%。
3. 具体材料名称以需求文档和已核验的渠道配置为依据，本方案不凭渠道名称臆造各渠道必交文件。
4. 将已上传记录按项目、材料类型、业务环节关联到同一清单；补录与业务模块引用同一材料记录，避免重复上传与重复统计。
5. “已上传”不等于“审核通过”；需审核材料以审核通过且符合要求计为齐备，不需审核材料以满足上传要求计为齐备。
6. 当前和历史阶段已触发的必交项构成“应交”范围，未来未触发材料单列为“后续需提供”，不算当前缺项。
7. 条件不适用材料显示原因，不纳入应交分母。配置确认无要求时显示“无适用材料”；无配置与无要求必须区分。
8. 齐备度按材料清单项计数，不按附件文件个数计数；一个材料项有多个版本仍只算一项。
9. 渠道或规则调整时保留既有文件和历史要求，明确差异，不静默删除材料或改写审批历史。

## 7. 保留下方业务标签页

保留顺序：**概览 → 里程碑 → 计划 → 经费 → 交付物 → 协作评价 → 成果转化 → 审批与归档 → 项目可视化**。沿用现有数量提示和各页内部布局，默认“概览”。

移除“补录归集”标签后，数据展示归属如下：

| 信息/附件 | 对应查看位置 |
|---|---|
| 项目目标、基本信息、团队及相关附件 | 概览 |
| 里程碑、完成佐证 | 里程碑 |
| 年度计划、执行计划及附件 | 计划 |
| 预算、支出、核销及凭证 | 经费 |
| 交付清单、成果文件 | 交付物 |
| 协作单位评价及附件 | 协作评价 |
| 成果包、转化进展及证明材料 | 成果转化 |
| 申报、备案、评审/评估、验收结论、变更、审批结果文件及材料历史版本 | 审批与归档，并允许阶段明细引用查看；不展示节点流转轨迹 |
| 项目可视化信息 | 项目可视化 |

不存在对应业务字段的历史材料仍需在相关阶段明细及“审批与归档”中可查，不因移除标签而失去访问入口。旧链接指向“补录归集”时回退到“概览”，不产生空白内容。

“审批与归档”保留名称与材料查看布局，只展示审批结果、结果文件及归档材料，不展开审批流程信息。“项目可视化”保留进度、经费、成果等项目视图，移除审批流转图及其入口。后台审批历史数据继续保留供对应业务页面查询。

截图中的经费双栏布局可保留，但“节点预算/里程碑”属于已有业务口径问题，最终应与已确认的“预算与核销均不绑定里程碑”一致。本方案不重新设计经费流程，也不把截图旧字段视为重新认可绑定关系。

## 8. 视觉与响应式规格

以下为建议值，实现时优先复用平台现有设计变量。

| 项目 | 建议 |
|---|---|
| 页面底色 / 内容底色 | 浅灰 / 白色，沿用现有蓝色品牌体系 |
| 分区间距 | 16px；分区内部间距 12–16px |
| 阶段卡片 | 内边距 12–16px、圆角 6–8px、1px 细边框，避免重阴影和嵌套卡片 |
| 生命周期收起高度 | 桌面端目标约 180–220px，长文本自然增长，不裁切必读内容 |
| 字号 | 阶段名称 16px；正文 14px；辅助说明 12–13px |
| 建立方式标签 | 高约 22px，与现有状态标签协调，仅出现一次 |
| 状态表达 | 蓝色当前、绿色完成、灰色未开始、橙色待补、红色异常，同时提供文字/图标 |
| 表格 | 保留现有紧凑行高，长文件名省略但可查看完整名称 |

在常见 1366px、1440px、1920px 桌面视口验证三个阶段全部可见，生命周期区域不出现横向滚动。窄屏采用纵向阶段排列；下方业务标签沿用现有适配方式，保证所有标签可访问。阶段选择、展开/收起、文件操作支持键盘焦点与明确的选中状态。

## 9. 权限与边界

- 本页展示始终受项目和文件访问权限约束，不能仅隐藏按钮而保留越权下载接口。
- 项目负责人通过左侧指定功能页面补充信息、上传和提交；导入项目使用“导入项目补录 → 我的补录”。
- 审核人员在本页仅查看、预览和下载；审核意见及审批动作进入左侧对应待审功能。审核权限不授予修改负责人内容的权限。
- 左侧“导入项目补录”及其待审、记录功能保留；“新建申报”入口保留。
- 生命周期的界面分组调整不自动发起审批、不补造历史节点、不推进项目状态。

- [ ] 两种建立方式仅通过一个小标签区分，其余结构一致。
- [ ] 相同渠道与适用条件的项目使用相同材料要求，建立方式不影响清单。
- [ ] 历史已完成且缺资料的项目显示“业务已完成、材料待补”，不错误退回业务阶段。
- [ ] 未来阶段可以查看材料名称和提交时机，未触发要求不算当前缺项。
- [ ] 当前事项显示真实办理人，待指定及渠道未识别均有明确提示。
- [ ] 生命周期节点只查看；展开阶段不改变下方业务标签选中状态。
- [ ] 阶段入口为“查看材料/查看要求”，不会打开原审批流转弹窗、抽屉或流程页面。
- [ ] 概览中“审批流转、实施流转、验收流转”入口移除；详情页所有标签均不展示审批链或逐节点流转轨迹。
- [ ] 阶段状态、当前责任人、材料审核状态及审批结果文件仍可按权限查看，详细流程统一在左侧业务功能中查看。
- [ ] “补录归集”标签移除，其余九个标签及原有内容布局保留，默认“概览”。
- [ ] 导入的基本信息、团队、里程碑、经费、交付物、成果转化信息与附件均可在对应位置查看。
- [ ] 审核人员不可修改、替换或删除负责人内容；预览与下载按权限校验。
- [ ] 1366px、1440px、1920px 桌面视口均完整显示三阶段，无生命周期横向滚动。
- [ ] 验收完成但转化未完成、不适用转化、无材料配置、附件多版本、空数据均有正确展示。

交付范围为本设计文档。后续实施须按本版边界修改页面，并核验材料映射、权限及上述场景。
