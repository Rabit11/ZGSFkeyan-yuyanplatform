# 测试入口修复与真实接口验证（上一轮）

当前的单地址隧道适配以 [隧道入口验证](07-单地址隧道入口验证.md) 为准。上一轮只在前端网关增加转发，仍未覆盖 API 直接到原后端的隧道部署。

## 问题与修正

旧入口在客户端拼接当前主机名加 `:6026`，而测试网关仅监听服务器本机。该设计依赖用户可访问另一个端口，在远程访问、HTTPS 代理或单端口转发下可能失败。此前的测试从服务器内部直接访问 6026，未验证用户从原平台点击按钮的路径，不能证明用户侧入口可用。

现已在原“项目变更”页面内切换演练模式：

1. 点击“进入测试模式”，通过当前访问地址的 `/api/changes/lab/auth/login` 正常登录独立测试后端。
2. 再读取后端 context，确认 `testMode=true` 才启用演练会话；默认使用演练负责人 100012。
3. 保持原平台 token 不变，演练 token 使用独立 sessionStorage 项；模块内切换身份只影响演练。
4. 所有项目变更操作使用真实 HTTP 接口，包括列表、保存、上传、下载、提交及审批；不调用全局 mock 适配器。
5. 连接失败显示错误和重试入口，不返回模拟成功、不切换到原平台写入。退出测试模式恢复原列表和原身份。

服务端网关和 Vite 开发代理只增加 `/api/change-lab` 专用转发，其他 API 继续使用原后端。原导航、登录页和其他业务组件未修改。

## 实测证据

验证脚本：`qa/change/entry.mjs`。测试从原平台 6006 登录、点击真正的入口按钮开始，主动阻断浏览器对 6026 的访问。

| 用例 | 结果 |
| --- | --- |
| E01 failed lab connection shows actionable error and never falls back to mock or formal writes | 通过 |
| E02 real entry succeeds inside port 6006 even while all browser connections to 6026 are blocked | 通过 |
| E03 UI saves a real change row and uploads a real attachment into isolated storage | 通过 |
| E04 switching test actors preserves formal session; two actual approvals write exactly once | 通过 |
| E05 exit restores original workbench and original data; no formal business rows changed | 通过 |

除入口专项外，原 20 项浏览器流程重新回归；当前类型检查、构建和 17 项前端规则/状态测试通过。其他业务页面另做 11 个路由冒烟验证。

已保留一份通过真实浏览器操作创建、上传及审批的演练申请，可在测试模式中搜索“入口修复验证”查看附件与完整履历。该证明记录不占用八个标准场景，其 project_no 前缀为 LAB_PROOF_；重跑入口专项会另外保留证明记录。

本次证明记录：项目 `LAB_PROOF_60`，申请 ID `93`。SQL 实测状态为 APPROVED；单位与总部各通过一次，仅产生一次 APPLY 回写事件；原平台业务数据快照不变。

证据：[结构化结果与真实请求路径](../../deploy/change-entry/results.json)、[页内入口截图](../../deploy/change-entry/01-entry.png)、[办结记录截图](../../deploy/change-entry/02-approved-proof.png)。

复现命令（仓库根目录，原平台与测试后端已启动）：

```bash
CHANGE_QA_DB=rpm_change_lab CHANGE_QA_BASE=http://127.0.0.1:6026 \
LD_LIBRARY_PATH="$PWD/.deploy-libs/rootfs/usr/lib/x86_64-linux-gnu" \
node qa/change/entry.mjs
```

这里的环境变量只供本机脚本建立、核对隔离数据库夹具；脚本中的浏览器入口仍是原平台 6006，并禁止直接访问 6026。

实际使用只需刷新原平台网页，进入“项目变更”，点击“进入测试模式”。不必访问 6026，不必退出原平台登录。测试模式不等于业务范围全部完成：历史只读、单字段申请及未明确渠道口径等边界继续见使用指南。
