# 分支部署与验证

分支：`feature/project-change-multiselect`。基于发布时远端 `main` 的 `3438363`，保留其生命周期展示调整和达索 UI 参考资料；本分支实现集中在项目变更模块。

## 交付范围

- 同一项目、同一申请内多选多个变更类别和对象，自动展开每项独立输入，一次提交所有变更项。
- 版本快照、审批权限、法务节点、周转人展示、附件及原子回写。
- 原页面内真实隔离演练、S01–S09 操作脚本和同源测试入口。
- 模块自动化测试、原始需求整理、平台架构文档及本地启停辅助脚本。

部署产物、依赖、运行中的数据库、附件、环境配置及随机密钥没有提交。文档中历史验收记录的申请 ID 和截图路径属于开发环境，不是代码仓库自带数据。

## 升级已有平台

1. 检出本分支，按原部署方式准备 Java 17、Maven、Node、MySQL、Redis 和 MinIO。
2. 在业务库依次执行 `backend/src/main/resources/db/migration_change_v2.sql`、`migration_change_v3.sql`。二者均为模块专属幂等建表；不要使用含 DROP 的 `schema.sql` 升级已有数据。
3. 使用原有环境配置运行 `mvn -f backend/pom.xml package`、`npm ci --prefix frontend`、`npm run build --prefix frontend`。
4. 按原部署方式发布前后端，继续使用现有入口和端口。正式法务名单由 `RPM_CHANGE_LEGAL_EMPLOYEES` 配置，不能把演练授权直接当作正式资格。

已有本地辅助环境可执行 `python3 scripts/local-platform.py start`；启动脚本会依次执行上述两个增量建表文件。脚本依赖已准备好的 `.deploy-libs` 和私有 `deploy` 配置，不能代替首次安装基础服务。

## 演练入口

`python3 scripts/change-lab.py start` 为独立演练库和对象存储配置演练后端。用户在原“项目变更”页面点击“进入测试模式”，浏览器访问当前地址的 `/api/changes/lab/...`。无需新增隧道映射。原后端内部连接本机演练服务；演练 SQL 与附件不写入正式业务库。

## 验证

常规检查：

```bash
npm run typecheck --prefix frontend
node --test qa/change/policy.test.mjs qa/change/workbench.test.mjs
mvn -f backend/pom.xml test
```

已部署独立演练环境可运行 `python3 qa/change/run-lab.py`。数据库/API/浏览器测试依赖本地演练数据库、MinIO 和 Playwright；脚本中的本机诊断服务地址不是需要用户新增的浏览器入口。

当前多对象交付在原运行环境完成 84 项/组检查，详见 [多类别多对象直接填写](09-多类别多对象直接填写.md)。发布分支在最新 main 基础上重新验证：TypeScript 检查通过，前端单元测试 26/26 通过，后端单元测试 43/43 通过，Vite 生产构建和 Maven package 均成功。实际用户隧道 URL 未提供，入口验证覆盖原端口和单地址 HTTPS 模拟。
