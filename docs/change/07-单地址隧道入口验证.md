# 单地址隧道入口修复

当前用法：在原平台地址打开“项目变更”，点击“进入测试模式”。无需增加隧道映射、修改浏览器端口或打开另一网址。更新后需重新加载原页面，使浏览器使用最新资源。

## 最终连接方式

浏览器只请求当前网页的地址：`/api/changes/lab/auth/login`、`/api/changes/lab/changes/...`。原后端的 ChangeLabBridgeController 验证原平台登录后，连接服务器内部的独立演练服务。无论前端网关处理 API，还是隧道将 API 直接交给原后端，都可以识别这组路由。

已撤销原平台网关及 Vite 中的测试专用转发。所有 API 继续走原 API 后端，不依赖新的客户端端口、跨域地址或代理前缀。浏览器请求基址也只取配置中的路径，避免构建配置把浏览器引到其他主机/端口。

原平台 JWT 继续用于原后端认证；演练 JWT 独立存储并随 X-Change-Lab-Token 传给桥接接口。缺少任一有效会话都不能调用演练业务。桥接只允许项目变更及演练登录，不允许其他业务接口、任意目的地址或递归转发。附件经相同入口上传和下载；不是浏览器直接连接附件服务器。

## 本轮还修复的运行问题

发现重新打包替换了正在运行的 JAR，导致旧 JVM 在后续加载类时出现 NoClassDefFoundError。两个应用现已改为从带内容哈希的独立 JAR 副本启动并已重启；后续构建不会覆盖运行中的文件。此调整属于启动脚本，不改变其他业务逻辑。

前端请求超时改用 AbortController，减少对浏览器 AbortSignal.timeout 支持的依赖。连接失败显示实际错误，不会回退到模拟数据或原平台写入。

## 验证方法与边界

- `qa/change/tunnel-api.mjs`：不经过前端专用网关，直接向原后端验证认证、真实演练登录/上下文及接口边界。
- `qa/change/entry.mjs`：以单一 HTTPS 浏览器地址模拟隧道，将 API 直接交给原后端。记录全部浏览器请求的 origin，要求只有一个；阻断浏览器对旧独立页面端口的访问。
- 页面操作覆盖失败重试、进入演练、创建草稿、真实附件上传/下载且字节一致、两级审批、仅一次数据库回写、退出演练及原平台数据/会话保持。

测试证据：`deploy/change-tunnel/api-results.json`、`browser-results.json`、构建及测试日志。模拟隧道地址仅用于自动化拦截，不是已发布的网址。

这证明单地址隧道访问模型下的本地实现通过。尚未收到用户实际隧道地址，因此没有把模拟结果表述为用户实际隧道已验通。

本轮最终结果：原后端直连检查 5/5，单地址浏览器流程 5/5，其他页面冒烟 11/11；43 项 Java 规则测试和 17 项前端状态/规则测试通过。最终模拟验证时间 2026-09-14T08:32:01.256Z，保留的真实演练申请 ID 为 109。
