科研项目信息化管理平台 · 项目台账 · 生命周期流程节点设计方案
================================================================================
来源：项目台账详情页界面截图（生命周期条 + 概览 Tab）+ 现有模块/渠道字典口径
沉淀日期：2026-09-09
说明：本文档沉淀「点开项目台账后」顶部六段生命周期流程节点、节点卡片信息、
      页面分区信息与交互规则，作为产品说明、开发对照与验收清单。
入口：项目总览 / 项目台账 → 点击项目名称 → 项目详情（全生命周期一本账）
对照实现（现状）：frontend/src/views/overview/ProjectDetail.vue
      （现状为 Descriptions + Tabs，尚无顶部六段生命周期条，本方案为目标设计）

一、设计目标与原则
--------------------------------------------------------------------------------
1. 目标：在项目台账详情页顶部，用「固定 6 段」平台级生命周期条，一眼看清项目
   走到哪一步、谁负责、下一流程谁办，并支持点击下钻详情/附件/办理轨迹。
2. 与「渠道流程」分工：
   - 平台生命周期（6 节点）：全渠道统一，用于台账进度总览与阶段跳转。
   - 渠道流程（按渠道配置，如 MJKY：建议书申报→…→国家级验收）：展示在
     「概览 · 项目信息 · 渠道流程」标签区，表达该渠道内部业务子步骤，
     不替代顶部 6 节点。
3. 与侧栏菜单对应：侧栏「立项 / 实施 / 验收 / 成果转化」等是业务办理入口；
   台账详情生命周期条是「单项目进度视图」，两者数据同源、入口互补。
4. 视觉：遵循商飞经营管理类 UI（商飞蓝标题栏、Ant 浅色后台）；
   节点态：已完成=绿勾、当前待办=蓝描边高亮、未开始=灰。


二、页面整体结构（自上而下）
--------------------------------------------------------------------------------
┌─────────────────────────────────────────────────────────────────────────────┐
│ A. 项目头区（名称 / 状态徽标 / 编号与元信息 / 经费与里程碑摘要）              │
├─────────────────────────────────────────────────────────────────────────────┤
│ B. 生命周期流程条（固定 6 节点 · 横向时间线）                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ C. 内容 Tab 区（概览 / 里程碑 / 计划 / 经费 / 交付物 / …）                    │
└─────────────────────────────────────────────────────────────────────────────┘

入口路径建议：
  项目台账列表 → 点击「项目名称」→ 本详情页
  面包屑示例：项目总览 / 项目台账 / {项目名称}


三、A 区 · 项目头区信息
--------------------------------------------------------------------------------
【左侧】
1. 项目名称（主标题，字号突出）
2. 状态徽标（可并列多个，语义色）：
   - 项目主状态：如「已完成」「实施中」「验收中」等（取 proj_info.status）
   - 阶段/归档提示：如「待归档」「验收中」（取当前生命周期节点推导）
3. 项目编号：如 KY-2026-001
4. 元信息一行（可换行）：
   - 项目层级：国家级 / 地方级 / 公司级
   - 渠道路径：部委/委局 → 司局/处室 → 渠道名
     例：工信部 → 装备二司 → MJKY
   - 管理/责任单位：如 中国商飞总部
   - 项目周期：YYYY.MM.DD – YYYY.MM.DD

【右侧 · 关键摘要三块】
1. 总经费：XX 万元（proj_info.totalFund）
2. 累计支出：百分比 + 已支出金额
   - 百分比 = 累计支出 / 总经费；无经费时展示 0%
3. 里程碑：已完成数/总数 + 进度条
   - 例：3/3，进度条满格为绿

头区不承载编辑；编辑仍走各业务模块（申报/备案/实施/变更等）。


四、B 区 · 生命周期流程节点总览（核心设计）
--------------------------------------------------------------------------------
固定 6 个平台级节点，顺序不可改、不可按渠道增减（渠道差异用「渠道流程」表达）。

编号 | 节点编码           | 节点名称         | 对应业务域
-----|--------------------|------------------|--------------------------------
01   | DECLARE            | 项目申报         | 立项 · 项目申报
02   | FILING             | 立项备案         | 立项 · 立项备案 → 生成项目主表
03   | IMPLEMENT          | 实施阶段         | 实施（里程碑/计划/经费/评估/变更）
04   | ACCEPT             | 项目验收         | 验收（验收材料/交付物/协作评价）
05   | TRANSFORM          | 成果转化         | 成果转化台账
06   | ARCHIVE            | 项目完成归档     | 审批与归档 / 台账办结

节点状态（三态）：
  DONE      已完成   —— 绿勾 + 绿色「已完成」标签
  TODO      待办     —— 蓝色描边卡片 + 蓝色「待办」标签（同一时刻最多 1 个）
  PENDING   未开始   —— 灰色卡片，无强标签或灰字「未开始」

推进规则（摘要）：
  01 申报审批通过（或无需审批且已提交报备）→ 可进入 02
  02 立项备案完成并生成 proj_info → 进入 03
  03 实施办结条件满足（见节点 03）→ 进入 04
  04 验收办结 → 进入 05（若渠道/项目无需转化，可配置跳过或标记「不适用」后进 06）
  05 成果转化办结或确认无转化事项 → 进入 06
  06 归档办结 → 项目生命周期结束；主状态可为「已归档/已完成」


五、各节点信息设计（卡片字段 + 办结条件 + 下钻内容）
--------------------------------------------------------------------------------
每个节点卡片统一字段模型：

  nodeCode / nodeName / seq
  status                 ：DONE | TODO | PENDING
  ownerRole              ：本节点「负责人」岗位名称
  ownerName              ：负责人姓名（从项目团队/申报岗位带出）
  finishStatus           ：已办结 | 办理中 | 未开始   （DONE 时展示「办结状态：已办结」）
  nextFlowName           ：下一流程名称（TODO/PENDING 时展示）
  nextHandlerRole        ：下一办理人岗位
  nextHandlerName        ：下一办理人姓名
  hint                   ：固定文案「点击查看详情、附件与办理轨迹」（TODO/可点节点展示）
  startedAt / finishedAt ：进入/办结时间（下钻抽屉用）
  bizRef                 ：关联业务单（申报单号 / 备案单 / 验收单等）

--------------------------------------------------------------------------------
节点 01 · 项目申报（DECLARE）
--------------------------------------------------------------------------------
卡片展示（图示口径）：
  - 标题：项目申报
  - 状态：已完成（示例）
  - 负责人 · 项目联系人：{姓名}
  - 办结状态：已办结

岗位映射：
  - 默认负责人岗位：项目联系人（申报填报岗；也可展示申报人）
  - 审批路径中的「当前节点」仍用申报单 flowNode（如：项目申报部门负责人、
    二级单位、一级单位、单位分管领导、总部科创部科研项目处等），在下钻抽屉
    「办理轨迹」中完整展示，不塞进顶部小卡片。

办结条件：
  - needApproval=1：审批通过（APPROVED）
  - needApproval=0：已提交报备且系统确认可备案
  - 驳回/撤销不算办结；卡片回退为办理中或退回填报

下钻抽屉建议 Tab：
  1) 申报基本信息（15 项基础字段摘要）
  2) 申报材料清单（按渠道自适应，含锁定项）
  3) 附件
  4) 办理轨迹（审批任务列表）

关联菜单：立项管理 → 项目申报

--------------------------------------------------------------------------------
节点 02 · 立项备案（FILING）
--------------------------------------------------------------------------------
卡片展示：
  - 标题：立项备案
  - 状态：已完成（示例）
  - 负责人 · 项目负责人：{姓名}
  - 办结状态：已办结

岗位映射：
  - 默认负责人岗位：项目负责人

办结条件：
  - 执行立项备案成功，生成项目主表 proj_info（编号、渠道、经费、专业、目标等回写）
  - 申报单状态转为已归档（REPORTED）等现网口径

下钻内容：
  - 备案信息（备案部门、备案时间、生成项目编号）
  - 从申报带入的主数据快照
  - 立项材料附件
  - 办理轨迹

关联菜单：立项管理 → 立项备案

--------------------------------------------------------------------------------
节点 03 · 实施阶段（IMPLEMENT）
--------------------------------------------------------------------------------
卡片展示：
  - 标题：实施阶段
  - 状态：已完成（示例）
  - 负责人 · 项目负责人：{姓名}
  - 办结状态：已办结

岗位映射：
  - 默认负责人岗位：项目负责人
  - 协同：技术负责人、项目主管、财务相关岗（在实施子模块办理）

办结条件（建议 AND，可按渠道裁剪）：
  - 里程碑全部闭环销项（或验收启动许可的里程碑完成比例达标）
  - 关键计划办结 / 无阻塞红灯
  - 节点经费匹配与付款核销满足验收前置检查（现网验收前置校验口径）
  - 无未结项的重大项目变更单

实施阶段内部工作（不拆成顶部节点，落入下方 Tab / 侧栏）：
  - 里程碑、计划、经费、评估检查、项目变更

下钻内容：
  - 实施摘要（里程碑完成率、经费执行率、未闭环项）
  - 关键附件与变更单列表入口
  - 办理轨迹（阶段进入/办结事件 + 关键审批）

关联菜单：实施阶段 → 各子功能

--------------------------------------------------------------------------------
节点 04 · 项目验收（ACCEPT）—— 图示当前「待办」节点
--------------------------------------------------------------------------------
卡片展示（图示口径）：
  - 标题：项目验收
  - 状态：待办（蓝高亮）
  - 负责人 · 项目负责人：{姓名}
  - 下一流程：二级单位管理团队办理人：{姓名}
  - 提示：点击查看详情、附件与办理轨迹

岗位映射：
  - 本节点负责人：项目负责人（发起/组织验收材料）
  - 下一办理：二级单位管理团队办理人（或单位科技主管等，按流程配置）
  - 可扩展：责任总师技术复核、公司级/机关级验收节点（在办理轨迹中展开）

办结条件：
  - 按项目层级完成对应验收（单位级 / 公司级 / 国家级或地方级）
  - 交付物应交尽交；协作评价到期规则满足（如需）
  - 验收结论通过，验收主记录办结

下钻内容：
  - 验收主信息（层级、状态、结论、复核标志）
  - 分级材料栏（非本层级 locked）
  - 交付物清单
  - 附件与办理轨迹

关联菜单：验收阶段 → 项目验收 / 交付物 / 协作单位评价
图示头区徽标可并列「验收中」等与本节点 TODO 态一致。

--------------------------------------------------------------------------------
节点 05 · 成果转化（TRANSFORM）
--------------------------------------------------------------------------------
卡片展示（图示口径 · 未开始灰态）：
  - 标题：成果转化
  - 负责人 · 项目负责人：{姓名}
  - 下一流程：二级单位管理团队办理人：{姓名}

岗位映射：
  - 负责人：项目负责人
  - 下一办理：二级单位管理团队办理人

办结条件：
  - 存在成果包时：转化状态达「已完成」或流程办结
  - 确认「无转化事项」并经管理岗确认 → 可标记本节点「不适用/已跳过」并进入归档
  - 转化核心信息同步台账与可视化看板（现网要求）

下钻内容：
  - 成果包列表（编号、方式、计划/实际时间、四色）
  - 与交付物绑定关系
  - 附件与办理轨迹

关联菜单：成果转化

--------------------------------------------------------------------------------
节点 06 · 项目完成归档（ARCHIVE）
--------------------------------------------------------------------------------
卡片展示（图示口径 · 未开始灰态）：
  - 标题：项目完成归档
  - 负责人 · 单位科技部长：{姓名}
  - 下一流程：二级单位管理团队办理人：{姓名}

岗位映射：
  - 本节点负责人：单位科技部长（归档确认）
  - 下一办理：二级单位管理团队办理人（办结归档操作）

办结条件：
  - 前置节点均已 DONE 或已确认跳过
  - 审批与归档资料齐全、流程办结
  - 项目主状态更新为已归档/已完成；台账只读为主，变更走审计例外流程

下钻内容：
  - 归档清单与归档意见
  - 全周期附件包
  - 完整办理轨迹

关联菜单：审批与归档 Tab / 系统审计可追溯


六、节点卡片交互
--------------------------------------------------------------------------------
1. 点击任一已进入过的节点（DONE / TODO）：右侧或底部打开「节点办理抽屉」
   （建议宽度 60%～70%），内含：详情、附件、办理轨迹。
2. PENDING 且不可达的节点：点击提示「请先完成上一阶段」或仅只读预览岗位配置。
3. 当前 TODO 节点卡片：描边高亮；支持快捷「去办理」跳转对应业务页并带 projectId。
4. 「查看审批流转」：与团队区按钮、节点抽屉轨迹同源，避免两套流程语义。
5. 生命周期条与下方 Tab：
   - 生命周期 = 阶段进度（Who / Where）
   - Tab = 资料与业务明细（What）
   - 建议：切换到与当前 TODO 相关的默认 Tab（如验收待办 → 可默认停在概览，
     并在概览提供「当前待办」一句话提示，避免与 Tab 抢视觉）


七、C 区 · 内容 Tab 页面信息（图示 9 Tab）
--------------------------------------------------------------------------------
Tab 顺序与命名（与图示对齐；角标为数量或完成数/总数）：

序号 | Tab 名称           | 角标示例 | 页面信息要点
-----|--------------------|----------|------------------------------------------
1    | 概览               | 无       | 见第八章（默认选中）
2    | 里程碑             | 3/3      | 年度里程碑列表、四色、销项、节点预算
3    | 计划               | 0        | CMOS/计划待办与完成、到期与责任人
4    | 经费               | 无或金额 | 节点预算 + 付款/核销；与总部预算账分离展示说明
5    | 交付物             | 3/3      | 类型、应交/实交、权属、关联成果编号、四色
6    | 协作评价           | 0        | 五维评分、总分、等级；不合格黑名单提示
7    | 成果转化           | 0        | 成果包列表；与节点 05 数据一致
8    | 审批与归档         | 无       | 全流程审签记录、归档材料、操作留痕入口
9    | 项目可视化         | 无       | 单项目维度图表/进度可视化（只读）

与现网 ProjectDetail Tab 差异说明（改造对照）：
  现网：项目所属信息 / 团队 / 科研年度目标及计划 / 里程碑 / 计划管理 /
        科研经费 / 评估检查 / 项目变更 / 验收 / 交付物 / 协作单位评价 /
        成果转化 / 后评价
  目标：按图示收敛为 9 Tab；「评估检查、项目变更」并入实施相关下钻或
        「审批与归档」；「后评价」若侧栏仍保留独立菜单，可不进台账主 Tab，
        或放入审批与归档子区。团队与所属信息并入「概览」。


八、概览 Tab（图示默认页）详细信息
--------------------------------------------------------------------------------
【左卡 · 项目信息】
1. 项目目标：全文
2. 年度目标：当前年或最近年度目标摘要
3. 项目渠道：与头区一致的渠道路径
4. 渠道流程：Tag 列表（来自 proj_channel.flowNodes，按「→」拆分）
   示例（MJKY）：
     建议书申报
     立项批复
     任务书/可研报告申报
     任务书/可研报告申报批复
     中期评估
     单位、公司两级验收评审
     国家级验收
5. 成果转化状态：暂无 / 未启动 / 洽谈中 / 已签协议 / 已完成
6. 协作单位：暂无或单位名称列表

【右卡 · 项目团队】
- 右上角操作：【查看审批流转】
- 成员列表（角色 + 姓名），图示示例岗位：
    项目负责人、技术负责人、项目主管、
    一级总师、二级总师、
    总部处室处长、单位科技部长、单位财务主管
- 数据来源：申报 13 岗 / proj_team_member；按技术/专家/管理/财务分组可在
  展开或「更多」中查看，概览默认扁平列表以免过重。


九、节点状态与项目主状态对照（建议）
--------------------------------------------------------------------------------
生命周期当前节点     | 项目主状态（示例）        | 头区徽标示例
---------------------|---------------------------|------------------
01 申报办理中         | （尚无项目主表或预生成）   | 申报中
02 备案办理中         | 待立项 / 立项中           | 立项中
03 实施               | 实施中                   | 实施中
04 验收               | 验收中                   | 已完成? + 验收中
05 成果转化           | 转化中 / 已通过验收       | 转化中
06 归档办理中/完成    | 待归档 / 已归档           | 待归档 / 已完成

说明：图示中「已完成」+「验收中」并存，表示业务完成度摘要与阶段态可并列，
开发时需产品确认「已完成」是指里程碑完成还是项目办结，避免双义。
建议：里程碑 3/3 完成 ≠ 项目已完成；项目「已完成」仅在 06 归档办结后打标。


十、数据与接口要点（开发备忘）
--------------------------------------------------------------------------------
1. 详情聚合接口建议扩展：
   GET /projects/{id}/overview
   增量返回：
     lifecycle: [
       { nodeCode, status, ownerRole, ownerName, nextFlowName,
         nextHandlerRole, nextHandlerName, finishedAt, bizRef }
     ]
     channelFlowNodes: string[]   // 渠道流程拆分
     summary: { totalFund, spentFund, spentRate, msDone, msTotal }
2. 节点办结事件写 biz_flow_instance / 或独立 proj_lifecycle_event 便于轨迹。
3. 负责人/下一办理人：优先项目团队岗；缺失时回退组织默认办理人配置。
4. 渠道流程与平台节点禁止混用同一组件数据源，UI 上分区展示（头下条 vs 概览 Tag）。
