# 五阶段信息填报入口统一 UI 方案

> 适用范围：项目申报、立项备案、实施、验收、成果转化五个阶段。  
> 目标：统一各功能页面的信息填报入口、页面结构和交互风格，让用户从任务栏进入对应功能页面完成填报、上传、提交、审核等业务操作。

## 1. 核心原则

### 1.1 信息填报入口统一从任务栏进入

所有填报、上传、提交、审核、退回后修改等操作，必须从左侧任务栏或对应功能菜单进入功能页面完成。

五个阶段的功能入口应统一为：

- 项目申报：`立项阶段 / 项目申报`
- 立项备案：`立项阶段 / 立项备案`
- 实施：`实施阶段 / 项目基本信息、里程碑填报、计划管理、项目经费、评估检查、项目变更`
- 验收：`验收阶段 / 项目验收、交付物管理、参研单位评价`
- 成果转化：`成果转化`

### 1.2 全流程禁止从流程节点入口上传

全流程不得从以下页面或组件进入填报、上传、提交、审核：

- 流程图节点
- 岗位泳道节点
- 生命周期节点
- 项目台账可视化节点
- 节点详情弹窗
- 图片类型或图形化页面中的节点按钮

这些页面只能用于查看状态、责任人、节点要求、材料清单、操作记录和只读附件，不允许出现上传、编辑、提交、审核等业务动作。

### 1.3 每个任务只保留一个业务提交入口

一个具体任务在功能页面内只保留一个主提交入口。字段填写、材料上传、校验提示、审核意见、历史记录都归集到同一个工作区内。

材料行可以支持查看、下载、选择文件、替换文件，但不能单独形成业务提交入口。最终业务动作统一由页面底部或表单区域的主按钮完成，例如：

- 提交项目申报
- 提交立项备案
- 提交年度里程碑
- 提交里程碑完成归档
- 提交验收申请
- 提交成果转化

### 1.4 可视化页面改为只读导航与状态说明

流程图、泳道图和生命周期视图保留展示价值，但定位调整为“看进度、看责任、看要求、看记录”。

允许保留的动作：

- 查看节点详情
- 查看材料清单
- 查看已上传附件
- 查看审批记录
- 跳转到对应功能页面的只读详情

不允许保留的动作：

- 上传材料
- 编辑表单
- 提交审批
- 审核通过或退回
- 从节点按钮直接进入可编辑填报页

## 2. 全局页面框架

五个阶段的功能页面使用同一套信息架构，降低用户切换成本。

### 2.1 页面顶部

顶部区域用于说明当前功能和当前项目上下文。

建议包含：

- 页面标题
- 当前阶段说明
- 项目搜索或项目选择
- 年度、批次、任务状态等筛选项
- 当前项目摘要信息

项目摘要建议使用紧凑信息条，而不是大面积卡片，展示：

- 项目编号
- 项目名称
- 负责人
- 承担单位
- 当前阶段
- 当前状态
- 最近更新时间

### 2.2 左侧任务列表

页面内部左侧保留任务列表或记录列表，用于快速切换待处理事项。

列表内容包括：

- 任务名称
- 所属项目
- 当前状态
- 责任人
- 截止时间
- 缺失材料数量
- 是否退回

列表支持按状态筛选：

- 全部
- 待我处理
- 草稿
- 已退回
- 审核中
- 已完成

### 2.3 右侧工作区

右侧作为唯一业务工作区，承载填报、材料、校验、提交和审核信息。

建议统一为四个区域：

- 基本信息
- 填报内容
- 材料清单
- 审核记录

对于字段较多的页面，使用页内分组和锚点定位，不建议使用多层弹窗承载主流程。

### 2.4 底部固定操作区

底部保留固定操作区，集中放置业务按钮和校验结果。

建议包含：

- 保存草稿
- 提交
- 审核通过
- 退回修改
- 撤回
- 返回列表

底部同时展示关键校验结果，例如：

- 还有 3 项必填未完成
- 还有 2 份材料未上传
- 当前任务已提交，等待部门审核
- 当前任务已退回，请补充说明后重新提交

## 3. 五个阶段页面方案

### 3.1 项目申报

项目申报页面作为申报材料的唯一填报入口。

页面结构：

- 申报任务列表
- 新建申报按钮
- 项目基本信息
- 申报书正文信息
- 预算或经费信息
- 申报材料清单
- 审核记录

保留能力：

- 新建申报
- 保存草稿
- 修改退回申报
- 上传申报材料
- 提交申报
- 查看审核意见
- 查看已办记录

交互要求：

- 申报材料必须在项目申报功能页上传。
- 申报流程图、泳道图、生命周期图只展示申报节点状态，不提供上传或提交入口。
- 待审核人员从“待我审核”或任务列表进入同一功能页审核，不从图形节点进入。

### 3.2 立项备案

立项备案页面作为备案信息和备案材料的唯一工作入口。

页面结构：

- 备案任务列表
- 项目摘要
- 备案基本信息
- 备案要求说明
- 备案材料清单
- 审核记录

保留能力：

- 填写备案信息
- 上传备案材料
- 保存草稿
- 提交备案
- 审核通过
- 退回修改
- 查看备案结果

交互要求：

- 立项备案材料不再从流程节点或项目台账节点上传。
- 立项备案流程图只展示备案进度、岗位责任和节点要求。
- 若项目台账中展示备案状态，只提供只读查看，不提供编辑入口。

### 3.3 实施阶段

实施阶段功能较多，需要保持现有功能完整，同时统一入口和工作区结构。

实施阶段包含：

- 项目基本信息
- 里程碑填报
- 计划管理
- 项目经费
- 评估检查
- 项目变更

统一页面规则：

- 每个实施功能从左侧实施阶段菜单进入。
- 每个功能页内部使用“任务列表 + 工作区”的结构。
- 项目、年度、任务状态在页面顶部统一筛选。
- 流程图只读展示实施进度，不承载上传、提交、审核动作。

#### 3.3.1 项目基本信息

保留项目实施期间的基本信息维护能力。

建议区域：

- 项目摘要
- 负责人和团队信息
- 承担单位信息
- 合同或计划信息
- 变更记录

业务动作统一在该功能页内完成。

#### 3.3.2 里程碑填报

里程碑填报需要同时覆盖年度里程碑编制、里程碑补充、里程碑完成归档和审核。

页面结构：

- 顶部年度选择
- 里程碑任务列表
- 年度里程碑编制区
- 里程碑节点清单
- 交付物或支撑材料清单
- 审核记录

保留能力：

- 编制年度里程碑节点
- 补充里程碑节点
- 上传里程碑支撑材料
- 提交年度里程碑
- 提交里程碑完成归档
- 部门审核
- 单位审核
- 退回修改

交互要求：

- 所有里程碑材料从“实施阶段 / 里程碑填报”进入上传。
- 实施阶段可视化流程中的里程碑节点只展示状态、要求、责任人和只读材料。
- 节点卡片上的“查看”只能打开只读详情，不能进入可编辑上传页。

#### 3.3.3 计划管理

计划管理用于维护实施计划、计划调整和计划执行情况。

页面结构：

- 计划任务列表
- 年度计划信息
- 计划内容
- 计划调整记录
- 支撑材料
- 审核记录

交互要求：

- 计划相关填报和材料上传只在计划管理页完成。
- 实施流程图只展示计划节点状态。

#### 3.3.4 项目经费

项目经费页面保留预算、预算填报、经费执行、核销或检查相关功能。

页面结构：

- 经费任务列表
- 预算填报区
- 经费执行区
- 核销或检查区
- 经费材料清单
- 审核记录

交互要求：

- 经费预算、预算调整、执行材料、检查材料都从项目经费功能页处理。
- 可视化节点不再出现“上传经费材料”“提交经费审核”等入口。

#### 3.3.5 评估检查

评估检查页面作为中期评估、阶段检查、问题整改的统一入口。

页面结构：

- 检查任务列表
- 检查要求
- 自查或填报内容
- 整改内容
- 支撑材料
- 审核记录

交互要求：

- 检查材料从评估检查功能页上传。
- 流程图只展示检查节点和状态。

#### 3.3.6 项目变更

项目变更页面作为变更申请、材料上传、审核流转的统一入口。

页面结构：

- 变更申请列表
- 变更类型
- 变更前后信息
- 变更原因
- 支撑材料
- 审核记录

交互要求：

- 变更填报和材料上传只在项目变更页完成。
- 流程图中若展示变更节点，只能查看状态和记录。

### 3.4 验收阶段

验收阶段包含项目验收、交付物管理、参研单位评价。验收申请作为验收阶段的主入口，交付物和评价保留独立功能页。

页面结构：

- 验收任务列表
- 验收前置条件检查
- 验收申请信息
- 验收材料清单
- 交付物汇总
- 参研单位评价汇总
- 审核记录

保留能力：

- 填写验收申请
- 上传验收材料
- 查看缺失材料
- 查看交付物完成情况
- 查看参研单位评价情况
- 提交验收
- 审核通过
- 退回修改

交互要求：

- 验收申请和验收材料只从“验收阶段 / 项目验收”进入。
- 交付物材料从“验收阶段 / 交付物管理”进入。
- 参研单位评价从“验收阶段 / 参研单位评价”进入。
- 验收流程图和生命周期图只做状态展示，不提供上传或提交入口。

### 3.5 成果转化

成果转化页面作为成果登记、转化信息填报和支撑材料上传的唯一入口。

页面结构：

- 成果转化任务列表
- 项目或成果摘要
- 成果基本信息
- 转化方式
- 转化进展
- 支撑材料清单
- 审核记录

保留能力：

- 新增成果转化记录
- 修改成果转化信息
- 上传转化材料
- 保存草稿
- 提交成果转化
- 审核通过
- 退回修改
- 查看转化记录

交互要求：

- 成果转化材料不从成果转化流程图节点上传。
- 成果转化图形页面只展示成果流转状态、责任岗位和历史记录。

## 4. 统一交互细节

### 4.1 状态表达

五个阶段统一使用相同状态语义。

| 状态 | 含义 | 建议颜色 |
| --- | --- | --- |
| 草稿 | 用户已填写但未提交 | 灰色 |
| 待处理 | 当前用户需要处理 | 蓝色 |
| 审核中 | 已提交，等待后续岗位处理 | 蓝色 |
| 已退回 | 被退回，需要修改 | 红色 |
| 临期 | 距截止时间较近 | 黄色 |
| 逾期 | 已超过截止时间 | 红色 |
| 已完成 | 流程完成或归档 | 绿色 |

### 4.2 材料清单

材料清单统一展示：

- 材料名称
- 所属环节
- 是否必传
- 当前状态
- 上传人
- 上传时间
- 操作

材料操作建议：

- 未上传：选择文件
- 已上传：查看、下载、替换
- 审核中：查看、下载
- 已完成：查看、下载

材料清单不单独提供业务提交按钮。

### 4.3 审核记录

审核记录统一展示：

- 操作时间
- 操作人
- 操作岗位
- 操作结果
- 审核意见
- 附件或补充说明

退回后，页面顶部应明显提示退回原因，并定位到需要修改的字段或材料。

### 4.4 保存与提交

保存和提交分离：

- 保存草稿只保存当前填写内容和材料选择状态。
- 提交会触发完整校验，并进入审批流。

提交前统一进行校验：

- 必填字段
- 必传材料
- 材料格式
- 材料大小
- 当前用户权限
- 当前任务状态

### 4.5 长表单处理

长表单不建议放在弹窗内。建议使用完整页面或抽屉，并提供：

- 分组标题
- 页内锚点
- 必填项提示
- 底部固定操作区
- 离开页面前未保存提醒

## 5. 可视化页面调整要求

需要统一检查以下可视化页面：

- 项目申报流程图
- 立项备案流程图
- 实施阶段流程图
- 验收流程图
- 成果转化流程图
- 项目台账生命周期视图
- 岗位泳道视图
- 节点详情弹窗

调整规则：

- 删除上传、编辑、提交、审核按钮。
- 删除进入可编辑表单页的节点跳转。
- 保留只读查看、材料查看、审批记录查看。
- 节点详情中明确显示“请从左侧任务栏进入对应功能页面办理”。
- 若需要跳转，只能跳转到对应功能页面的只读详情或列表定位，不直接进入可编辑状态。

## 6. 实施优先级

建议按以下顺序推进：

1. 项目申报：先做统一入口样板，确定页面骨架、材料清单、底部提交区。
2. 立项备案：复用申报页结构，沉淀备案页面标准。
3. 实施阶段：先处理里程碑填报，再扩展到计划、经费、评估检查、变更。
4. 验收阶段：先处理项目验收，再接入交付物和参研单位评价的只读汇总。
5. 成果转化：按统一工作区结构收口成果填报和材料上传。
6. 全流程可视化页面：统一改为只读状态展示，清理节点级业务入口。

## 7. 验收标准

本轮 UI 调整完成后，应满足以下标准：

- 五个阶段所有填报入口均来自左侧任务栏或对应功能菜单。
- 流程图、泳道图、生命周期图中不存在上传、编辑、提交、审核入口。
- 每个业务任务只有一个主提交入口。
- 字段填写、材料上传、审核意见、历史记录在同一个功能页面内闭环。
- 原有业务功能没有减少，原有角色权限和审批链路保持完整。
- 页面风格符合经营管理类系统统一 UI 规范。
- 用户能从任务列表快速识别待办、缺失材料、退回原因和下一步操作。

## 8. 开发检查清单

开发时逐页核对：

| 检查项 | 要求 |
| --- | --- |
| 功能是否保留 | 原有填报、上传、提交、审核、退回、查看能力不能丢失 |
| 入口是否统一 | 业务动作必须从任务栏或功能菜单进入 |
| 图形页面是否只读 | 流程节点不能承载上传、编辑、提交、审核 |
| 提交入口是否唯一 | 同一任务只保留一个主提交按钮 |
| 材料是否归集 | 材料清单在功能页内统一维护 |
| 审核记录是否完整 | 保留操作人、岗位、时间、意见、结果 |
| 状态是否一致 | 五个阶段使用统一状态语义和颜色 |
| 退回是否清晰 | 退回原因和修改位置必须明确 |
| 长表单是否可用 | 有分组、锚点、保存提醒和固定操作区 |
| 权限是否正确 | 不同角色只看到自己可处理的动作 |
