一、设计目标与原则
--------------------------------------------------------------------------------
1. 目标：在验收阶段用「审批流转图 + 右侧详情/附件面板」讲清：
   - 实施办结后能否发起（前置四项必须全绿）；
   - 按项目层级开放哪些材料栏、谁审、退回谁补正；
   - 办结后如何进入协作单位评价（30 天倒计时）及成果转化。
2. 与「台账生命周期」分工：
   - 台账顶部 6 段中的「04 项目验收」是阶段总览卡片；
   - 本方案是阶段内部办理细节（点击验收节点 /「查看详情与附件」下钻）。
3. 与「实施阶段流转图」分工：
   - 实施办结条件满足（里程碑闭环 + 关键计划办结 + 经费核销达标
     + 评估无阻塞不合格 + 无未结重大变更）→ 进入本阶段；
   - 本阶段办结：对应层级验收结论通过、材料齐套、主记录 DONE
     → 开启协作评价 30 天倒计时 → 生命周期可进「05 成果转化」。
4. 两层视图（对应两张截图，同一抽屉、同一数据源）：
   A. 审批流转总览（截图 1）：前置校验清单 + 组织泳道审批流；
   B. 办结与材料链（截图 2）：办结信息 + 分级附件 + 审查/办理链条。
5. 「交付物」「协作单位评价」是本阶段兄弟菜单，不拆成生命周期节点：
   - 交付物齐套是发起前置；
   - 协作评价是办结后 30 日内必办事项（截图主按钮「去协作单位评价」）。
6. 「指标办归档」是本阶段材料归档动作，不等于生命周期 06「项目完成归档」。
7. 视觉：商飞蓝（#0064EF）+ Ant 浅色后台。
   节点类型色（与实施阶段一致）：
     蓝描边 = 确认 / 上传（办理）
     绿描边 = 审核
     黄描边 = 系统自动
     紫描边 = 流程已结束且合规
   节点状态色：
     已办=绿勾、当前=蓝高亮、待办/未到=灰、退回=红、逾期=红预警。
   前置校验：通过=绿点，未通过=红点；未通过禁止提交。

2.2 独立办理页（现网 Acceptance.vue，与抽屉同源）
--------------------------------------------------------------------------------
侧栏「验收阶段 → 项目验收」：选择项目 + 前置校验按钮 + 提交申请 + 分级材料表。
抽屉负责「看清走到哪、谁办、材料齐不齐」；办理页负责「上传 / 提交 / 审核动作」。
两者字段、状态、材料清单必须同源，禁止两套口径。

入口路径建议：
  1) 项目台账详情 → 生命周期「项目验收」→【查看详情 / 查看流转】
  2) 验收阶段 → 项目验收 → 页头「查看验收流转」
  3) 待办审批 → 验收申请 / 初审 / 终审任务 → 打开本抽屉并定位当前节点
  4) 右侧面板主按钮 → 跳转协作评价 / 去办理 / 去审核（按当前态）

弹窗 / 抽屉标题：
  项目验收 · 详情与附件

副标题拼接（空项省略）：
  {项目编号} · {项目名称}

截图示例：
  KY-2026-002 · 杨会冉测试3
本平台演示建议：
  KY-2026-002 · {项目名称} · 负责人：林晚晴（100012）
  （截图中「林晓琴」为演示名，落地姓名一律用工号花名册）


三、流程节点总览（核心设计）
--------------------------------------------------------------------------------
3.1 验收审批流（截图 1 泳道，主路径）
--------------------------------------------------------------------------------
编号 | 节点编码              | 节点名称（展示）                 | 泳道（组织）         | 类型     | 截图态
-----|----------------------|------------------------------------|----------------------|----------|--------
A0   | ACCEPT_GATE          | 发起前置校验                      | 系统                 | 系统     | 全绿通过
A1   | ACCEPT_APPLY         | 验收申请                          | 项目团队             | 办理/上传 | 已办
A2   | ACCEPT_UNIT_REVIEW    | 初审                              | 二级单位管理团队     | 审核     | 已办（菱形：通过/退回）
A3   | ACCEPT_CHIEF_REVIEW  | 责任总师技术复核                   | 责任总师             | 审核     | 按层级：国家级必办
A4   | ACCEPT_HQ_TECH       | 技术初审                          | 行业总部             | 审核     | 已办（菱形：通过/退回）
A5   | ACCEPT_HQ_FINAL      | 终审                              | 总规管理团队         | 审核     | 已办
A6   | ACCEPT_ARCHIVE       | 指标办归档                        | 指标办               | 系统办结 | 已办结

说明：
  - A0 不是审批节点，是发起闸门：四项全绿才允许 A1 提交。
  - A3 由 proj_acceptance.expertReview 控制：国家级默认需要；公司级/地方级默认不需要，
    不需要时流程图折叠该节点，办理链条不展示空岗。
  - 截图 1 用组织泳道名（项目团队 / 二级单位 / 行业总部 / 总规管理团队）；
    截图 2 用岗位链名（责任总师技术复核 / 总部管理团队终审）。
    本方案约定：A4 = 行业总部技术初审；A5 = 总规管理团队终审 = 总部管理团队终审。
  - A6 只归档本阶段验收材料，不替代生命周期 06。

退回支路（审核不通过，不计入主路径序号）：

编号 | 节点编码              | 节点名称（展示）                 | 类型     | 触发
-----|----------------------|------------------------------------|----------|------
R1   | ACCEPT_RETURN        | 退回项目团队补正材料并重提         | 异常回流 | A2 / A4 菱形「退回」
R2   | ACCEPT_RE_AUDIT      | 补正后再审                         | 审核     | 回到被退回的那一级

3.2 状态工作流（产品一句话）
--------------------------------------------------------------------------------
实施办结 → 系统跑前置四项 → 项目团队上传本层级材料并提交申请
  → 二级单位初审 →（国家级）责任总师技术复核 → 行业总部技术初审
  → 总规/总部管理团队终审 → 指标办归档、验收主记录办结
  → 开启 30 天协作单位评价倒计时 → 可进入成果转化。

审核不通过 → 退回项目团队补正 → 再从被退回节点续审，不新开验收单。

3.3 节点状态枚举
--------------------------------------------------------------------------------
  DONE      已办     —— 绿勾 / 绿描边
  CURRENT   当前     —— 蓝描边高亮
  PENDING   待办/未到 —— 灰
  RETURN    退回     —— 红
  CLOSED    已办结   —— 紫或绿「已完成」徽标（整段结束）


四、各节点信息设计
--------------------------------------------------------------------------------
节点统一字段：

  nodeCode / nodeName
  status / statusLabel          ：已办 | 当前 | 待办 | 退回
  desc                          ：第二行说明
  lane                          ：泳道名（项目团队 / 二级单位管理团队 / …）
  actionRole                    ：岗位 · 动作
  handlerName / handlerLabel    ：姓名（工号），取花名册
  actionLabel / actionPath      ：去办理 / 去审核 / 去补正
  opinion                       ：同意 / 退回 + 意见（审核节点）
  materials[]                   ：本节点相关附件摘要

人选优先取项目团队对应岗；缺失时回退组织默认办理人（与实施阶段一致）。

--------------------------------------------------------------------------------
节点 A0 · 发起前置校验（闸门，截图 1）
--------------------------------------------------------------------------------
展示：区块标题「发起前置校验」
类型：系统自动 + 可手动重跑
岗位行：系统 · 校验
动作：【前置条件校验】（办理页） / 进入抽屉时自动刷新

四项清单（截图口径，必须同时通过）：

  编码            | 展示名称                 | 通过条件                              | 通过示例文案
  ----------------|--------------------------|----------------------------------------|---------------------------
  MILESTONE       | 里程碑全闭环             | 全部里程碑 status=DONE                 | 全部里程碑已完成销项
  CORE_DV         | 核心交付物齐套           | 核心/必交交付物均已交付；外协无逾期     | 核心交付物已交付 x/x
  FUND            | 经费核销与凭证归档       | 节点付款均已核销且凭证已归档            | 已归档 1 张凭证，累计 10 万元
  EVAL_RECTIFY    | 不合格评估整改            | 无未闭环的不合格评估/整改单             | 无待整改不合格项

现网对照：
  现状 check 接口为：里程碑闭环 / 外协交付物未逾期 / 经费核销完毕 / 核心交付物已交付。
  目标以截图四项为准：把「外协未逾期」并入 CORE_DV；新增 EVAL_RECTIFY。
  任一项未通过：红点 + 禁止 A1 提交；禁止静默灰掉按钮，须展示 checks 清单。

去上传               | CURRENT = A1 或 R1             | 办理页材料栏 / 上传抽屉
去审核               | CURRENT = A2/A3/A4/A5          | 打开审核表单（通过/退回+意见）
去协作单位评价       | 已办结（截图主按钮）             | 跳转 /acceptance/partner
进入成果转化         | 已办结且评价不阻塞（或可并行）   | 跳转 /transform
关闭                 | 始终                              | 关抽屉

6.4 发起前置校验（截图 1）
--------------------------------------------------------------------------------
四行清单，每行：状态点 + 名称 + 结果短句。
全部通过：绿点；失败：红点 + 失败原因（如「仍有 2 个里程碑未闭环」）。
与办理页 Alert 清单同源。

6.5 验收审批流（截图 1 中区图）
--------------------------------------------------------------------------------
横向/折行泳道：
  项目团队（验收申请）
    → 二级单位管理团队（初审，菱形 通过/退回）
    → 行业总部（技术初审，菱形 通过/退回）
    → 总规管理团队（终审）
    → 指标办归档
A3 责任总师：国家级时插在 A2 与 A4 之间，可用小节点或链条展开，避免泳道过挤。
退回线画回「项目团队」，不要另起一条与主路径平行的成功节点。

6.6 审查 / 办理链条（截图 2）
--------------------------------------------------------------------------------
当前流向条：
  办理中：当前节点名称 + 办理人
  已办结：已办结 - 待归档（截图原文）

链条卡片（默认可折叠，截图「展开完整链条」）：
  岗位名称、办理人、工号、状态（已办/当前）、日期、意见（同意/退回）

截图 2 可见两项：
  1) 责任总师技术复核 · 已办 · 同意
  2) 总部管理团队终审 · 已办 · 同意
  「展开完整链条（2）」= 还有 A1/A2 等前序节点，默认收起已办前序，突出最近两级。

建议默认：当前节点 + 最近 2 条已办；展开后按 A1→A6 全量时间线。

九、协作单位评价（办结后必办，截图主按钮）
--------------------------------------------------------------------------------
规则（现网保留）：
  - 参研单位：自项目验收完成（DONE）起 30 日内完成评价；
  - 外协单位：自外协合同验收后 30 日内完成评价；
  - 5 维度各 20 分：技术能力 / 交付质量 / 进度履约 / 服务配合 / 合规性；
  - 优秀≥90、良好≥80、合格≥60、不合格<60 自动入黑名单；
  - 提交后不可改。

与本阶段关系：
  - 不阻塞 A6 办结（办结后才倒计时）；
  - 逾期走四色预警（黄≤30 天已在倒计时内提示，超期红）；
  - 不替代生命周期 05；评价完成可作为转化/归档的提示，不强制 AND（除非渠道另配）。


十、数据与接口要点
--------------------------------------------------------------------------------
现网已有：
  GET  /api/acceptance/{projectId}              详情 + 分级材料 items
  POST /api/acceptance/{projectId}/check      前置校验
  POST /api/acceptance/{projectId}/submit    提交申请（校验失败拒绝）
  POST /api/acceptance/{projectId}/materials  上传分级材料
  POST /api/acceptance/{projectId}/audit     一键办结（现状过粗）

目标补齐（与申报/实施 flow 对齐）：
  GET  /api/acceptance/{projectId}/flow
    header: { projectCode, projectName, ownerLabel, panelStatus, acceptLevel, expertReview }
    checks: [{ key, label, passed, message }]
    nextAction / nextActionPath
    nodes: [{ nodeCode, nodeName, lane, status, handlers, opinion, actionLabel }]
    items: 分级材料 + 文件行
    timeline: 审查链条
    finishAt / partnerDueDate / conclusion

  POST /api/acceptance/{projectId}/audit
    改为按当前节点通过/退回：{ nodeCode, pass, opinion }
    终审通过时服务端串联 A6：DONE + 30 天倒计时
    禁止跳过 A2/A3/A4 直接办结（现状 audit 一键 DONE 需收敛）

check 四项与第三节 A0 对齐；CORE_DV 含外协未逾期；新增 EVAL_RECTIFY。

主表字段（已有）：
  acceptLevel / status / applyAt / finishAt / conclusion / expertReview / partnerDueDate
材料表：levelCode, materialName, locked, status, fileUrl


十一、交互规则
--------------------------------------------------------------------------------
1. 右侧抽屉宽度按规范大档（约 70%）；复杂审批流也可用居中宽弹窗，
   但标题、区块顺序须与截图一致。点 × / 关闭 / 遮罩关闭。
2. 前置未通过：主按钮不可提交，同时用 checks 清单说明原因，禁止静默禁用。
3. 非本层级材料栏锁定，操作按钮 disabled，文案「本项目不适用 · 已锁定」。
4. 菱形「退回」必须填意见；通过意见可默认「同意」。
5. 退回回到项目团队补正，不新开验收单、不新增成功路径节点。
6. 办结后材料只读，主按钮切为「去协作单位评价」。
7. 人员展示一律花名册工号，不用截图演示名。
8. 侧栏 / 台账详情 / 待办跳同一项目的同一 flow URL。
9. 视觉遵循商飞经营管理类 UI：主色 #0064EF，按钮高 32px，
   禁止深色驾驶舱风套到经营管理主站。
10. 危险操作（退回、办结）二次确认；成功/失败用 Message。
