# 平台回归测试

在工程根目录“给会冉”运行。依赖使用已有 frontend/node_modules。

## 本地回归

```powershell
node qa/run-platform-checks.mjs
```

检查 TypeScript 类型、真实 Vue 页面组件的异步项目切换、批量核销校验、重复点击、部分失败重试、加载失败、流程状态，以及内存模拟环境中的表单维护和台账权限。

## 线上接口巡检

```powershell
$env:RPM_BASE_URL='https://u476948-r3ys-6923790a.westd.seetacloud.com:8443'
$env:RPM_TIMEOUT_MS='30000'
node qa/run-platform-checks.mjs --live
```

线上检查查询业务数据，并用不存在的测试编号验证越权写操作被拒绝，不提交真实项目审批。现有脚本默认使用演示账号。仅在测试环境证书不受本机信任时，按已有部署环境设置 RPM_INSECURE_TLS=1；正常证书环境不需要此设置。

汇总报告：output/platform-checks-latest.md。每组日志分别保存；脚本遇到失败仍收集其他组结果，最终以非零退出码报告失败。WARN 表示样本缺失或未覆盖，不能当作全量业务验证通过。

## 独立写入验证

```powershell
node qa/file-roundtrip-smoke.mjs
python deploy/run-platform-regression.py
```

第一个脚本生成唯一 QA 文本附件，使用二级单位财务上传，验证中文文件名和下载内容，最后用管理员删除本次产生的附件。

第二个脚本连接已配置的服务器，创建独立 QA 项目和里程碑，验证负责人提交、承担部门审核、单位科研管理部门审核，以及财务核销的数据校验和角色权限。在 finally 中按本次创建的编号清理 QA 业务记录。不会重启服务或发布代码；运行需要已有 SSH 环境和 Python 的 Paramiko 依赖。操作审计日志可能保留测试调用痕迹。

部署脚本 deploy/deploy-form-maint-6006.py 同样包含上述隔离流程校验，失败时回滚应用文件。

## 测试边界

这组检查覆盖目前确认的高频问题及关键流程，不等同于压力测试、完整安全审计或所有页面的浏览器测试。历史重复、超预算或乱码样本应单独核对，不由回归脚本自动冲销或删除。
