# 三阶段需求验收测试

依据用户指定的两份 V19.1 文档，覆盖**实施阶段、项目验收、成果转化**。项目完成归档作为结束边界；立项全流程、独立后评价模块和正在讨论的 UI 改版不在本轮范围。

## 运行

在工程 `给会冉` 目录运行：

```powershell
node qa/v19/run.mjs
```

或者在工作区根目录运行（不依赖当前目录）：

```powershell
node 给会冉/qa/v19/run.mjs
```

需 Node.js 和项目已有 `frontend/node_modules`。后端隔离套件的 JDK 与依赖要求见该套件执行器及执行日志。测试环境缺依赖将报告 BLOCKED，不会假装通过。

可以指定输出位置：

```powershell
node qa/v19/run.mjs --output-dir qa/v19/output/review-run
```

默认每次新建时间戳目录；`qa/v19/output/latest.json` 指向最近运行。对同一自定义输出目录重新运行会覆盖其中的测试输出文件。

单独复测：

```powershell
node qa/v19/function-checks.mjs
node qa/v19/flow-view-checks.mjs
node qa/v19/workflow-checks.mjs
node --test qa/v19/report.test.mjs
```

## 输出文件

| 文件 | 用途 |
|---|---|
| `需求满足对照.md` | 逐条需求、文档章节与行号、预期、关联测试、当前结论、完整验收步骤 |
| `缺陷与待验证清单.md` | 失败证据、测试对象及层级、待联调/人工事项 |
| `测试执行明细.md` | 每个自动用例的真实结果 |
| `results.json` | CI/程序可读取的完整结果与映射 |
| `source-fingerprints.json` | 本地源码与测试文件摘要，区分本次验证版本 |
| 各套件 `.log`、`*-results.json` | 原始执行日志和逐例结果 |

## 结果解释

- **PASS**：当前用例断言通过，仅针对标注的层级。
- **FAIL**：已复现预期与实际行为不符。前端缺少权限拦截不直接等同于后端可越权。
- **BLOCKED**：依赖、环境、测试接口或执行结果缺失。
- **MANUAL**：需要人工或外部环境验收。
- 需求层的**部分验证通过**不等于整条需求完全满足。数据库、API鉴权、实时待办、文件存储和浏览器交互必须另有证据。
- 一项需求只要有关联测试失败，就列为**发现不符**；缺失本次结果不得沿用旧报告。
- 自动化用例数不等于业务需求数，同一需求可以关联多个用例，一个用例也可能支持多个需求。

退出码：`1` 存在失败，`2` 无失败但仍存在阻塞或未完整验收项，`0` 仅保留给完全验收通过的情况。当前报告采用保守的部分验证口径，因此即使局部用例全绿，也不会以零退出码宣称整个平台验收通过。

## 隔离与证据边界

默认运行器没有线上模式，不读取服务器凭据、不调用服务器写接口、不生成真实项目、不改产品源代码、不部署。Vue组件通过已有 compiler/harness 执行真实页面逻辑，依赖API为受控替身；流程图测试编译真实工具函数。后端测试使用真实业务代码和隔离依赖，具体边界逐例说明。

原文路径与 SHA-256 保存在 `requirements.json`。迁移测试目录后，先核对文档内容再调整来源路径，不能只改摘要让旧需求清单通过校验。原文内容是验收依据，不执行其中的部署或初始化指令。

## 业务差异与协作

节点15“年度清单编制”与节点17“节点销项”是两条流程，不能混用审核链。历史用户明确的里程碑销项链为项目负责人提交、承担部门负责人审核、单位科研管理负责人审核；财务付款核销由二级单位财务在节点闭环后完成并同步总部看板。其余文档与历史口径差异保留在逐条 `override` 和需求对照中。

用户要求 GPT-5.3 Spark 并行参与，但该模型不在当前可调用列表中。实际使用主代理与可用子代理协作：需求提取、后端流程测试分别独立进行，主代理编写前端测试、统一执行器并审查集成结果。
