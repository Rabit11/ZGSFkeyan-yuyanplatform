# 实施阶段模块测试用例（V19.1）

## 1. 测试依据和流程口径

本测试用例以《科研项目全生命周期流程节点责任人与填报上传信息说明 V19.1》的实施阶段节点十四至节点二十二作为业务验收标准，覆盖项目基本信息补充、年度目标与里程碑清单编制、里程碑预警与执行、里程碑完成与材料审核、计划同步与办结、经费预算填报、经费核销、评估检查、项目变更和数据变更。

现有代码项目作为测试执行入口和差异定位依据，主要入口包括：

| 模块 | 前端页面 | 主要接口 |
|---|---|---|
| 项目基本信息补充 | `/implement/basic`、`/implement/review` | `/api/projects/{id}`、`/api/projects/{id}/maintenance/*` |
| 年度目标与里程碑 | `/implement/milestone`、`/implement/milestone-close` | `/api/projects/{projectId}/milestones`、`/api/milestones`、`/api/milestones/annual-plan/audit` |
| 里程碑完成审核 | `/implement/milestone-close`、`/implement/review` | `/api/milestones/{id}/materials`、`/api/milestones/{id}/close`、`/api/milestones/{id}/close-audit` |
| 计划管理 | `/implement/plan` | `/api/projects/{projectId}/plans`、`/api/plans/sync`、`/api/plans/{id}/finish-*` |
| 经费预算与核销 | `/implement/fund` | `/api/projects/{id}/fund/budgets`、`/api/fund/budgets`、`/api/fund/payments`、`/api/fund/payments/{id}/writeoff` |
| 评估检查 | `/implement/evaluation` | `/api/projects/{projectId}/evaluations`、`/api/evaluations` |
| 项目变更 | `/implement/change` | `/api/changes`、`/api/changes/{id}/submit`、`/api/changes/{id}/audit` |
| 待办、已办、审计 | `/implement/review`、我的已办、审计日志 | `/api/fund/reviews/pending`、`/api/audit-logs/mine/done`、`/api/audit-logs` |

需求文档是业务正确性来源；如果现有代码与 V19.1 不一致，测试结论应记录为差异或缺陷，不把当前实现反推为验收标准。

## 2. 角色与数据准备

| 测试角色 | 需求岗位 | 主要验证点 |
|---|---|---|
| 项目团队成员 | 项目团队、项目联系人、项目负责人、技术负责人、项目主管 | 填报、暂存、提交、补正、只读查看 |
| 项目负责人 | 项目负责人审核、验收及总体事项 | 收到指定待办、审核通过/驳回、本人提交仍进入负责人审核 |
| 单位科技管理部 | 单位科技主管、单位科技部长、二级单位科技部门 | 基本信息审核、年度清单存档、里程碑核验、评估初审 |
| 单位分管领导 | 单位分管领导 | 基本信息复核、不可越权改业务字段 |
| 总部科研项目处 | 总部处室主管/处长 | 基本信息确认、评估/变更终审、台账同步 |
| 二级单位财务 | 单位财务主管、单位财务部长 | 预算审核、核销材料上传、本级核销 |
| 总部财务团队 | 总部财务主管 | 预算复核备案、总部看板同步核对 |
| 非当前节点人员 | 任意非指定人员 | 页面无操作按钮，接口越权失败 |

建议准备 4 类项目样本：

| 样本 | 状态 | 用途 |
|---|---|---|
| A | 已立项备案，基本信息未补齐 | 基本信息补充、退回、台账不提前覆盖 |
| B | 基本信息有效，年度清单未审核 | 年度目标与里程碑编制、预算前置条件 |
| C | 有蓝/黄/红/绿里程碑 | 四色预警、延期变更限制、完成审核 |
| D | 里程碑闭环、预算备案、待核销 | 经费预算、核销、总核、同步看板 |

## 3. 端到端主流程用例

| 编号 | 节点 | 用例名称 | 前置条件 | 操作步骤 | 预期结果 |
|---|---|---|---|---|---|
| IMPL-E2E-001 | 14-22 | 实施阶段完整正向流转 | 项目已完成立项备案，岗位人员和工号完整 | 项目团队补充基本信息并提交；项目负责人、单位科技管理部、单位分管领导、总部科研项目处依次通过；技术负责人编制年度目标与里程碑清单并由二级单位科技部门审核；完成里程碑材料上传与审核；同步计划并办结；填报预算并两级财务审核；对应里程碑闭环后财务核销；完成评估检查和项目变更审批 | 每个节点只给指定人员生成待办；审批通过后进入本人已办；正式台账、预算台账、经费看板只在最终通过后更新；审计日志保留提交人、审批人、意见、附件版本 |
| IMPL-E2E-002 | 14-22 | 驳回补正后重新提交 | 任一审核节点处于待审 | 审核人填写意见并驳回；项目团队补充材料后再次提交；原审核链继续流转 | 驳回待办关闭，补正人收到待办；原材料、驳回意见、补正附件均保留版本；再次通过后进入下一节点 |
| IMPL-E2E-003 | 14-22 | 非当前节点人员越权拦截 | 流程处于任一审核节点 | 使用非当前办理人的账号打开页面并直接调用审批接口 | 页面不显示审批按钮；接口返回无权限；不生成已办，不改变业务状态 |
| IMPL-E2E-004 | 14-22 | 人员岗位缺失时禁止提交 | 项目团队岗位缺少项目负责人、单位科技部长或财务岗位 | 尝试提交基本信息、年度清单、预算或核销 | 提交失败并提示缺失岗位；不得生成空角色待办 |

| IMPL-BASIC-003 | 审批链正确流转 | 信息和材料完整 | 项目团队提交后依次登录项目负责人、单位科技管理部、单位分管领导、总部科研项目处处理 | 待办按“项目团队填报 → 项目负责人审核 → 单位科技管理部审核 → 单位分管领导复核 → 总部科研项目处确认”流转 |
| IMPL-BASIC-004 | 未最终通过前不覆盖正式台账 | 基本信息处于审批中 | 修改目标、周期或经费后提交但不终审 | 项目正式台账仍显示原审批生效值；审批草稿/流程详情显示新值 |
| IMPL-BASIC-005 | 审核人不得覆盖填报区 | 当前用户为审核人 | 在审核页尝试修改项目团队填报字段 | 只能填写审批意见或按权限替换附件；业务字段不可直接保存 |

## 12. 自动化脚本覆盖说明

配套脚本：`qa/implementation-stage-v19-checks.mjs`。

脚本默认执行本地静态检查，覆盖：
