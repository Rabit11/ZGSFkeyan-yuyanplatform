一、设计目标与原则
--------------------------------------------------------------------------------
1. 目标：用竖向流转图讲清立项备案阶段：
   申报办结衔接 → 负责人上传本渠道必传支撑材料 → 归口审核（可驳回补正）
   → 通过后台账转「实施中」。
2. 与台账生命周期分工：
   - 台账顶部「02 立项备案」= 阶段总览；
   - 本图 = 阶段内部办理细节（点击备案节点 /「查看流转」下钻）。
3. 与申报流转图分工：
   - 申报审签/线上报备办结后进入本阶段；
   - 本阶段办结：支撑材料审核通过 → 台账状态转为实施中 → 生命周期进「03 实施」。
4. 与渠道 filingMaterial 分工：
   - 底部红框「立项支撑材料（本渠道必传）」= 按渠道字典动态列出的必传件；
   - F2 节点内材料摘要行与底部红框同源（同一渠道材料清单）。
5. 视觉：商飞蓝 + Ant 浅色后台；
   已办=绿描边、办结/进入实施=蓝描边、本渠道必传清单=红描边说明框。

三、流程节点总览（与截图一一对应）
--------------------------------------------------------------------------------
主路径自上而下 4 步（无第 5 个流程节点）：

编号 | 节点编码             | 节点名称（展示）                       | 类型     | 截图态
-----|----------------------|----------------------------------------|----------|--------
F1   | FILING_DECLARE_DONE | 申报审签 / 线上报备办结                | 前置衔接 | 已办（绿）
F2   | FILING_SUBMIT       | 项目负责人提交立项支撑材料             | 上传办理 | 已办（绿）
F3   | FILING_AUDIT        | 科研归口管理部门审核                   | 审批     | 已办（绿）
F4   | FILING_PASS_IMPL    | 立项支撑材料审核通过，进入实施阶段     | 系统办结 | 蓝描边

底部说明框（非流程节点）：

区域 | 编码                 | 展示标题                               | 样式
-----|----------------------|----------------------------------------|------
M1   | FILING_CHANNEL_MAT  | 立项支撑材料（本渠道必传）             | 红描边说明框

状态工作流：
  申报办结 → 材料上传 → 归口审核 → 通过进实施
  审核驳回 → 退回项目负责人补正（回到 F2）→ 再审

节点状态枚举：
  DONE      已办   —— 绿描边 + 角标「已办」
  CURRENT   当前   —— 蓝描边高亮（办理中）
  PENDING   未到   —— 灰描边
  F4 在办结完成后可用蓝描边表示「结果/跳转」态；整段办结后当前节点条显示空态。


四、各节点信息设计（截图字段口径）
--------------------------------------------------------------------------------
节点统一字段：

  nodeCode / nodeName
  status / statusLabel          ：已办 | 当前 | 待办
  desc                          ：第二行说明文案
  actionRole                    ：岗位 · 动作（如：项目负责人 · 上传）
  handlerName / handlerLabel    ：办理人「姓名」或「姓名（工号）」
  materials[]                   ：仅 F2 展示材料摘要（与渠道必传同源）

--------------------------------------------------------------------------------
节点 F1 · 申报审签 / 线上报备办结
--------------------------------------------------------------------------------
展示（截图原文）：
  标题：申报审签 / 线上报备办结
  说明：上一节点完成后进入立项支撑材料办理
  办理行：系统 · 已办

语义：
  - 承接申报阶段办结事件（需审批=审签通过；无需审批=线上报备办结）
  - 进入备案后本节点自动 DONE，办理人为「系统」（非人工再审）

办结条件：
  - 申报单已可备案（APPROVED / 报备完成）

--------------------------------------------------------------------------------
节点 F2 · 项目负责人提交立项支撑材料
--------------------------------------------------------------------------------
展示（截图原文）：
  标题：项目负责人提交立项支撑材料
  材料摘要行：立项通知、任务书、任务流程、合同、立项批复
              （实际按渠道 filingMaterial 动态拼接，上列为 MJKY 示例）
  办理行：项目负责人 · 上传
  办理人：系统管理员（100001）   ← 示例数据，取项目负责人岗实际人选
  状态：已办

岗位映射：
  - 主办理岗：项目负责人（OWNER）
  - 动作：上传
  - 权限：filing_upload

材料：
  - 与底部「本渠道必传」清单一致
  - 齐套后方可「提交审核」

驳回回流：
  - F3 驳回后回到本节点 CURRENT，按意见补正/替换附件后重提

--------------------------------------------------------------------------------
节点 F3 · 科研归口管理部门审核
--------------------------------------------------------------------------------
展示（截图原文）：
  标题：科研归口管理部门审核
  说明：驳回则退回项目负责人补正
  办理行：单位科技部长 · 审批
  办理人：方致远（100005）   ← 示例
  状态：已办

岗位映射：
  - 主审核岗：单位科技部长（UNIT 科技归口）
  - 动作：审批
  - 可按层级扩展总部归口会签（轨迹展开；主图仍一个审核节点）

审核动作：
  - 通过 → F4
  - 驳回 → 退回 F2（文案已写明；不单独画「必须退回件」流程节点）

--------------------------------------------------------------------------------
节点 F4 · 立项支撑材料审核通过，进入实施阶段
--------------------------------------------------------------------------------
展示（截图原文）：
  标题：立项支撑材料审核通过，进入实施阶段
  说明：台账状态转为实施中
  样式：蓝描边（结果/跳转节点）

系统动作：
  1) 备案流程办结
  2) 生成/确认项目主表（若尚未生成）
  3) 项目主状态 / 台账状态 → 实施中
  4) 生命周期：02 FILING = DONE，03 IMPLEMENT = TODO
  5) 当前节点条 →「立项备案暂无进行中节点」

--------------------------------------------------------------------------------
底部说明框 M1 · 立项支撑材料（本渠道必传）
--------------------------------------------------------------------------------
展示（截图原文）：
  标题：立项支撑材料（本渠道必传）
  列表：立项通知、任务书、任务流程、合同、立项批复
  样式：红描边说明框（强调必传，不是退回流程节点）

规则：
  - 文案「本渠道必传」= 取当前项目渠道的 filingMaterial（及平台约定扩展项）
  - 与 F2 材料摘要行同源；渠道切换则列表变化
  - MJKY 截图示例五件：立项通知 / 任务书 / 任务流程 / 合同 / 立项批复
  - 勿与旧稿「立项摘要、任务预算、立项背景、必须退回件」混淆


五、流向
--------------------------------------------------------------------------------
5.1 成功主路径
--------------------------------------------------------------------------------
F1 申报审签 / 线上报备办结（系统 · 已办）
  ↓
F2 项目负责人提交立项支撑材料（项目负责人 · 上传）
  ↓ 提交审核
F3 科研归口管理部门审核（单位科技部长 · 审批）
  ↓ 通过
F4 审核通过，进入实施阶段（台账状态转为实施中）
  ↓
生命周期 · 实施阶段

5.2 驳回路径（文案驱动，不增节点）
--------------------------------------------------------------------------------
F3 驳回
  ↓ 「退回项目负责人补正」
F2 重新上传/提交
  ↓
F3 再审 → …

5.3 截图状态对照（KY-2026-004）
--------------------------------------------------------------------------------
- 副标题状态：实施中 → 备案已办结、已进入实施
- 当前节点条：立项备案暂无进行中节点
- F1/F2/F3：绿 · 已办
- F4：蓝描边结果态
- 底部红框：本渠道必传材料说明（始终展示清单，非异常态）


六、本渠道必传材料（数据口径）
--------------------------------------------------------------------------------
展示名称（截图） | 建议材料编码        | 来源
-----------------|---------------------|----------------------------------
立项通知         | FILING_NOTICE      | 渠道 filingMaterial / 平台字典
任务书           | FILING_TASK_BOOK   | 同上
任务流程         | FILING_TASK_FLOW   | 同上
合同             | FILING_CONTRACT    | 同上
立项批复         | FILING_APPROVAL    | 同上（渠道常配「立项批复」）

附件列表项字段：材料名、已传/未传、文件名、上传时间、预览/下载/替换
提交审核前：未传必传件拦截

十、数据与接口要点
--------------------------------------------------------------------------------
GET /filings/{id}/flow 建议返回：
  header: { projectCode, projectName, projectStatus, channelName }
  currentTip: string          // 如「立项备案暂无进行中节点」
  nodes: [
    { nodeCode, nodeName, desc, actionRole, handlerLabel, status, materials? }
  ]
  channelMaterials: string[]  // 底部红框 + F2 摘要同源
  timeline: [...]

动作：
  POST .../attachments   上传/替换
  POST .../submit        F2 提交
  POST .../audit         { result: PASS|REJECT, comment }
  （PASS 时服务端串联 F4：台账转实施中）

现网 POST /declarations/{id}/filing 收敛为 F4 落库实现，前置必须 F2/F3 完成。


十一、交互规则
--------------------------------------------------------------------------------
1. 居中遮罩弹窗；点 × / 遮罩关闭。
2. 主路径仅 4 节点；驳回用 F3 说明文案表达，不画第五个流程节点。
3. 底部红框固定为「本渠道必传」材料说明，勿做成「必须退回件」流程节点。
4. 办结后当前节点条显示「立项备案暂无进行中节点」。
5. 视觉遵循商飞经营管理类 UI。
